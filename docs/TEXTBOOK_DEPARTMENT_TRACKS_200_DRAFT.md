# 藤本実学塾 ChatGPT実践教科書 主要20部門×10「仕事が変わる」チャレンジ

> 状態: 再設計ドラフト（20部門×10チャレンジ、全200問）
> 更新日: 2026年9月1日
> 位置づけ: 担当業務に合わせて選ぶ専門トラック

全教材の役割、重複時の正本、コース間の乗換え方は、[カリキュラム全体地図](./TEXTBOOK_CURRICULUM_MASTER_MAP.md)を先に確認してください。

## 明日の仕事で「これが使える」を一つずつ作ろう

**「何を覚えるか」より、「明日どんな仕事ができるようになるか」。自分の部門で使いたくなる作品を、AIと少しずつ完成させます。**

全員に共通する制作課題は、[共通200チャレンジ](./TEXTBOOK_PROBLEM_BANK_200_DRAFT.md)で扱います。この部署別200問は、その続きとして全員がLv.201〜400を順番に解くものでも、全員必修の追加200問でもありません。自分の担当業務、目標、会社の課題に合わせて選ぶ**専門トラック**です。小規模会社や一人で複数の役割を担う人は、必要な部門を一つずつ追加できます。現在の主プロジェクトは一つにします。

自分の会社・店・専門分野の仕事を入口から完了まで一つの作品にしたい場合は、[業種別10コース×10チャレンジ](./TEXTBOOK_INDUSTRY_TRACKS_100_DRAFT.md)を使います。業種別で弱い機能が見つかった時に、この部署別トラックで担当機能を深掘りすることもできます。

部署で必要になった本、SNS、画像、動画、Web、広告、スライド、教材、ゲーム、スマホアプリ、Excel等の制作・体験品質を深める場合は、[生成特化23タイプ×10チャレンジ](./TEXTBOOK_GENERATION_TRACKS_200_DRAFT.md)を使います。たとえば広報の企画をInstagram10投稿へ、営業提案を編集可能なPowerPointへ、見積条件を毎月使えるExcelへ育てられます。

保存場所と会話の分け方は、[学習構造案](./TEXTBOOK_LEARNING_STRUCTURE_DRAFT.md)を使います。部署別では「選んだ1部門＝1専門プロジェクト」としますが、10問を一本の長いチャットでは進めません。`01〜03`、`04〜06`、`07〜10`の工程ごとにチャットを分け、最新の完成品と`ここまでメモ.md`で次へ渡します。部署横断の全体卒業制作を始める時だけ統合プロジェクトを作ります。

### 現場の資料は、いちばん簡単な形で渡す

部門の仕事では、依頼がメール本文、チャット、PDF、Word、Excel、画像、共有フォルダ等、毎回違う形で届きます。各課題は、材料が短文なら本文をコピーして貼り、書式付き資料なら添付します。両方使っても構いません。単発ならChat、実ファイルを作る・同じ成果物を直し続けるならWorkをすすめ、Workの入力欄でも同じ渡し方を使います。

AIが読めなければ、フォルダ参照のまま粘らず、同じChatまたはWorkの入力欄へファイルを添付し、それでもだめなら必要部分を貼ります。Workが表示されない場合は、Chatへの貼付・添付と本人による保存で同じ完成条件へ進みます。読めなかった資料名をAIに言わせます。入力方法は採点しません。Chatの成果物は本人がコピーまたはダウンロードして保存し、Workの成果物はAIへ保存を頼んだ後に本人が開きます。

旧設計は、業務地図、役割整理、KPI定義、評価表などの抽象課題が中心でした。新設計では、提案ページ、受付アプリ、承認画面、ダッシュボード、定期レポート、自動処理など、受講後に「AIでこの具体物を作れた」と見せられる制作課題を中心にします。

### このコースで作るところ・ほかのコースから借りるところ

- **担当する:** 部門の担当者、KPI、承認、上流・下流、部門固有の例外と人判断。
- **担当しない:** 画像・文章・動画・Webの専門的な制作技法、業種全体の入口から提供完了までの再現。
- **共通編との重複:** 共通のDB、認証、承認、連携、安全キットを開始見本として使い、部門固有の項目と差分試験だけを加える。
- **生成特化との重複:** 部署で企画・承認する内容を生成特化へ渡し、採用版を部門業務へ戻す。媒体作品を本書でゼロから作り直さない。

### すでに作ったものは、上手に引き継ごう

各問を始める前に、プロジェクトの「できたもの一覧」へ同じような成果物があるか確認します。あれば、人が完成条件を比べて次のいずれかを選びます。管理用ファイル名やコードは教材編集者が裏側で管理し、初心者ページには出しません。

1. **移行認定（合格相当）:** 本問の全完成条件を満たす既存成果物だけを、証拠付きで合格版として認める。入力素材として使えるだけなら移行認定にせず、差分改善を選ぶ。
2. **差分改善:** 部門固有の不足だけを追加する。
3. **新規制作:** 同等成果物がない時だけ白紙から作る。

標準は03または06の後、または[全体地図のコード単位クロスウォーク](./TEXTBOOK_CURRICULUM_MASTER_MAP.md#高重複コースのコード単位クロスウォーク)で指定された出発課題の後に、制作品質が足りない時だけ生成特化へ途中分岐できます。`ここまでメモ.md`へ出発課題、到着先、渡す事実・素材、戻る課題、再制作しない物を書き、生成側の採用版を元部門へ戻してから**次の未完了課題**を再開します。問を飛ばせるのは、その問の全完成条件を満たし、課題ごとの移行認定（合格相当）を証拠付きで残した場合だけです。編集者用の管理ファイル名は生徒ページに出しません。

## 10問で、単品から「仕事の相棒」へ育てよう

各部門の10問は、ばらばらの勉強ではありません。最初は今日使える1枚から始め、最後には上司や仲間へ見せて試せる一つの仕事道具へ育てます。

**01〜03 すぐ使える単品 → 04〜06 画面・ツール → 07 部署間連携 → 08 定期更新 → 09 安全装置 → 10 架空データの通し試験**

| 段階   | 作るもの                                               | 到達点                                                                                             |
| ------ | ------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| 01〜03 | 文書、表、メール、チェック票、調査レポートなど         | その日から仕事で使える単品を完成させる                                                             |
| 04〜06 | ページ、フォーム、アプリ、比較画面、シミュレーターなど | 複数の情報を扱える画面・ツールにする                                                               |
| 07     | 前工程・後工程との引継ぎ                               | 部署間で同じ案件を安全につなぐ                                                                     |
| 08     | 定期集計、通知、レポート更新                           | 繰り返し業務を人の確認付きで自動化する                                                             |
| 09     | 権限、承認、出典、停止、復旧、監査履歴                 | 失敗を検知し、止め、戻せる機能を組み込む                                                           |
| 10     | 架空データでの通し試験                                 | 受付から完了、停止・復元までを模擬し、処理時間、漏れ、誤り、人の修正回数を「教材試験値」として測る |

### 今の気分で選べる3つの進め方

- **らくらく**: 選んだ部門の01〜03。まず単品を3つ完成させる。
- **標準**: 01〜06。単品を、入力・検索・比較ができる画面やツールへ育てる。
- **実務挑戦**: まず01〜10を架空データで完成させる。その後、組織が許可した場合だけ、対象者・期間・データ・停止条件を限った別の限定運用で実測する。

## 白紙から始めないために、最初から用意するもの

部門名だけを変えた同じ問題にはしません。各部門には、次の4点を固有に用意します。

1. **練習データ**: その部門で実際に扱う会話、文書、表、画像、例外ケース。
2. **AIが決めない判断**: 採否、評価、契約、支払、公開、出荷、安全、予算など、人が責任を持つ判断。
3. **上流・下流**: どこから情報を受け取り、誰へ何を渡すかが分かる引継ぎ。
4. **効果指標**: 時間、漏れ、誤り、差戻し、手直し、期限超過、復旧性など、導入前後を比べる数字。

## 安心して仕事で使うために、人が決めること

AIは候補、差分、根拠、下書き、通知を作ります。責任を伴う最終判断は人が行います。安全は注意書きだけでなく、各部門の09で製品機能として実装し、10で失敗ケースまで試します。

| 領域                 | AIが支援すること                   | 人が決めること                         |
| -------------------- | ---------------------------------- | -------------------------------------- |
| 採用・人事・労務     | 発言整理、不足確認、日程・例外候補 | 採否、人事評価、懲戒、給与確定         |
| 経理・購買・法務     | 計算、照合、条文差分、承認資料     | 振込、口座変更、発注、署名、法的結論   |
| 製造・品質・物流     | 計画候補、異常候補、影響範囲       | 設備操作、出荷可否、安全判断、実配送   |
| 広報・営業・顧客対応 | 調査、返信案、提案案、反応分類     | 外部送信、公開、価格約束、返金・補償   |
| IT・全社改善         | 権限候補、変更案、進捗・異常通知   | 本番権限付与、本番変更、予算・優先順位 |

実在する顧客、応募者、従業員、取引先の情報は、許可、利用目的、保存期間、削除方法、閲覧権限を確認するまで教材へ入力しません。授業では架空データを基本とし、実務挑戦では承認済みの仮名化・マスキング済みデータだけを使います。AIだけで法的な匿名化を保証しません。

## 01｜経営・経営企画 — 朝5分で会社の今と次の一手が見える

> 10問後に手に入るもの: 重要数字、未決裁、リスク、予定を一画面で確認できる「AI経営コックピット」

- **MGT-01｜社長メモを入れるだけで、今日決めることが見える1枚を作ろう** — やってみること: 断片的なメモから、今期の重点、重要数字、課題、未確認事項、決めたいことを整理し、書かれていない事実は加えない。できあがるもの: 出典箇所と確認待ちを表示した1ページ経営ブリーフ。〔会話・ファイル・成果物・人の確認〕
- **MGT-02｜「今月はどうだった？」を一目で話せる数字レポートを作ろう** — やってみること: 架空の売上、粗利、固定費、現金、顧客数を前月・計画と比べ、変化、原因仮説、確認先を分ける。できあがるもの: 月次経営サマリーと確認質問一覧。〔ファイル・データ・架空データ・成果物〕
- **MGT-03｜経営会議で「今日は何を決める？」が伝わる8枚を作ろう** — やってみること: 部門報告、月次数字、未決事項を、結論、根拠、選択肢、リスク、判断依頼の順でまとめる。できあがるもの: 編集可能な経営会議スライドと発表者メモ。〔ファイル・データ・成果物・人の確認〕
- **MGT-04｜売上や人数を変えたら未来がどうなるか、3つの案で比べてみよう** — やってみること: 売上、人員、原価、投資の前提を動かし、基準・上振れ・下振れの現金と利益を比較できるようにする。できあがるもの: 前提を編集できる3シナリオ試算画面。〔データ・試作・架空データ・人の確認〕
- **MGT-05｜案件を入れると、決める前に見たい材料がそろうメモを作ろう** — やってみること: 案件情報を入力すると、選択肢、費用、効果、反対材料、可逆性、確認待ちを同じ形式で出すようにする。できあがるもの: 決裁メモ生成フォームと3件の出力例。〔成果物・試作・架空データ・人の確認〕
- **MGT-06｜半年後も「なぜそう決めた？」に答えられる記録を残そう** — やってみること: 決定、保留、却下、前提、承認者、見直し日、宿題を検索でき、後から判断理由を確認できるようにする。できあがるもの: 変更履歴付き経営判断ログ画面。〔データ・試作・架空データ・人の確認〕
- **MGT-07｜毎朝5分で、会社の今と今日見ることが分かる画面を作ろう** — やってみること: 教材用の予定、重要メール、重要指標（KPI）、ニュース、未決裁から、その日確認すべき項目だけを集める。できあがるもの: 出典リンクと更新時刻付きの朝ダイジェスト。〔検索・ファイル・連携・定期実行・人の確認〕
- **MGT-08｜社長が見るべき異常と未決裁だけが集まる箱を作ろう** — やってみること: 金額、期限、変化率、重要度の条件を満たした案件だけを通知し、経営者が承認・保留・差戻しできるようにする。できあがるもの: 通知条件付き経営承認キュー。〔データ・連携・定期実行・試作・人の確認〕
- **MGT-09｜見せてよい人だけが見られる、安全な経営画面にしよう** — やってみること: 部門別閲覧権限、数値の出典、承認前の外部送信禁止、操作履歴、緊急停止、手動資料への復帰を架空データで試す。できあがるもの: 権限・承認・停止機能付きコックピットと安全テスト記録。〔データ・連携・試作・架空データ・人の確認〕
- **MGT-10｜架空の1か月分で、会社専用の「朝の経営画面」を完成させよう** — やってみること: 架空の1か月分の経営データで会議準備から判断記録までを通し、準備時間、確認漏れ、誤警告、手直しを測る。できあがるもの: AI経営コックピット、運用ガイド、効果測定、継続・改善・停止の判断資料。〔ファイル・データ・成果物・連携・試作・架空データ・人の確認〕

## 02｜事業企画・新規事業 — アイデアを「試して決める」形まで育てる

> 10問後に手に入るもの: 顧客の証拠、市場試算、検証LP、実験結果を一つにつなぐ「新規事業検証スタジオ」

## 本の1ページにするとき、毎回つけるもの

精査後、採用する各チャレンジを次の順で本文化します。

1. **今日はこれを作る:** その部門で今日手元に残る具体物、ファイル形式、最初の完成までの目安。
2. **使うもの・今回はどう渡す:** 材料は短文なら貼り、見た目や表が大事なら添付する。作業画面は一回ならChat、実ファイルを作って何度も直すならWorkと分けて示し、追加資料は使う前に名前と理由を示す。
3. **まずこう言ってみる:** 現場の人が普段口にする、短くて少し雑な最初の一言。
4. **出てきた物を実際に触る:** 開く、担当をたどる、数字を変える等、受講者本人が行う一つの操作。
5. **出力を上げるコツ:** 根拠、前提、例外、担当、確認者が足りない時に、三つ以内から一つ選ぶ短い一言。
6. **やりがちなミス:** 数字違い、担当漏れ、権限外、引き継ぎ忘れなど、先に見つけたい失敗。
7. **ここまでできたら完成:** 開けた、使えた、合っていた、権限外で止まれた、保存できた、から本問に必要な三条件。通常チャット・添付は本人が保存し、WorkはAIへ保存を頼んだ後に本人が開く。
8. **自分の仕事なら:** 自分の担当へ一か所だけ置き換える小さな応用。新しい機能や次の課題はここへ混ぜない。
9. **困ったら藤本に聞く:** 画面、課題名、使ったファイル、止まった所をまとめる短い相談メモ。
10. **ステップアップ:** 今回の完成品を正本のまま使う次の課題IDまたは総仕上げ、担当業務へ一つの目的として便利になる内容、同じ会話へ送る短い一言。任意であり、現在の課題の合否には含めない。
