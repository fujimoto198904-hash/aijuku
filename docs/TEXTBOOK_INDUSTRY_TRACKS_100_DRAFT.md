# 藤本実学塾 ChatGPT実践教科書 業種別10コース×10チャレンジ

> 状態: 初稿（10業種×10チャレンジ、全100問） / 採用前の精査用
> 更新日: 2026年9月1日
> 位置づけ: 自分の会社・店・専門分野に近い「作ってみたい」を、10問で一つの完成作品へ育てる選択コース

全教材の役割、重複時の正本、コース間の乗換え方は、[カリキュラム全体地図](./TEXTBOOK_CURRICULUM_MASTER_MAP.md)を先に確認してください。

タイトルは、覚える知識の名前ではなく、**10問後に見せられる景色への入口**です。まず自分の仕事に近い章を開き、01〜10のタイトルを眺めて「これがあったらうれしい」と思うコースを一つ選んでください。分からない言葉があっても、最初から全部理解する必要はありません。ChatGPTと一緒に、見本を動かしながら覚えていきます。

## 自分の仕事に近い「これを作りたい」から始めよう

**業界知識を暗記するのではなく、その業種で「AIを使ってここまで作った」と見せられる実用品を完成させる。**

この業種別100問は、[共通200チャレンジ](./TEXTBOOK_PROBLEM_BANK_200_DRAFT.md)や[主要20部門×10チャレンジ](./TEXTBOOK_DEPARTMENT_TRACKS_200_DRAFT.md)の後に、全員が順番に解く追加Lv.401〜500ではありません。自分が経営・勤務・支援している業種から、必要な1コースだけ選べます。共通編の完走は前提にしません。各コースは架空データと課題の開始素材から始め、まだ用意できていない完成見本を「ある前提」にはしません。

業種コースで作った会社、商品、サービス、顧客像を使って、本、Instagram、画像、動画、Web、広告、ゲーム、スマホアプリ、Excel等の一作品・体験をさらに作り込む場合は、[生成特化23タイプ×10チャレンジ](./TEXTBOOK_GENERATION_TRACKS_200_DRAFT.md)へ進みます。逆に、生成特化で作った素材をこの業種別コースへ戻し、受付・運営・顧客接点へ組み込むこともできます。

保存場所、ChatGPTのプロジェクトとチャットの分け方、次の課題への引き継ぎ方は、[学習構造案](./TEXTBOOK_LEARNING_STRUCTURE_DRAFT.md)を使います。業種別は「選んだ1業種＝1専門プロジェクト」が基本です。ただし、10問を一本の長いチャットにせず、`01〜03`、`04〜06`、`07〜10`の工程ごとに分け、完成品と`ここまでメモ.md`を次へ渡します。

### 店や現場の資料は、いちばん簡単な形で渡す

実際の材料は、予約メモ、チャット、PDF、Word、Excel、写真、複数フォルダ等、業種や場面で変わります。各課題は、材料が短文なら本文をコピーして貼り、書式付き資料なら添付します。両方使っても構いません。単発ならChat、実ファイルを作る・同じ成果物を直し続けるならWorkをすすめ、Workの入力欄でも同じ渡し方を使います。

AIが読めなければ、フォルダ参照のまま粘らず、同じChatまたはWorkの入力欄へファイルを添付し、それでもだめなら必要部分を貼ります。Workが表示されない場合は、Chatへの貼付・添付と本人による保存で同じ完成条件へ進みます。読めなかった資料名をAIに言わせます。入力方法は採点しません。Chatの成果物は本人がコピーまたはダウンロードして保存し、Workの成果物はAIへ保存を頼んだ後に本人が開きます。

部署別案に挙げていた8テーマのうち、「宿泊・観光」は宿泊施設と観光・体験サービスへ、「建設・不動産」は建設・リフォームと不動産仲介・管理へ分けました。扱う顧客接点、データ、法的・安全上の責任、人が決める事項が異なるためです。これにより、全10コースとしています。

### このコースで作るところ・ほかのコースから借りるところ

- **担当する:** 一つの業種で、顧客の入口から提供、引渡し、改善までを複数部署にまたがってつなぐ。
- **担当しない:** 汎用のDB・認証・連携部品を毎回作り直すこと、各部署の専門統制をすべて教えること、画像・Web等の専門制作を極めること。
- **共通編との重複:** 共通の開始見本を複製し、この業種の事実、データ項目、役割、禁止操作へ交換する。
- **部署別との重複:** 業種別は会社全体、部署別は一担当機能。同じ案件を両方で完走せず、弱い機能だけ部署別へ分岐する。
- **生成特化との重複:** 業種側が商品、料金、注意事項、顧客、公開条件を渡し、生成側の採用画像・サイト・投稿を業種作品へ戻す。

### 見た目や文章をもっと磨きたくなったら

標準は03または06の後、または[全体地図のコード単位クロスウォーク](./TEXTBOOK_CURRICULUM_MASTER_MAP.md#高重複コースのコード単位クロスウォーク)で指定された出発コードの後に、見た目・文章・媒体品質だけを深めたい場合は生成特化へ分岐できます。「できたもの一覧」に同等成果物があれば新規生成せず「移行認定（合格相当）」または「差分改善」を選びます。移行認定にできるのは本問の全完成条件を満たす既存成果物だけです。受講者は`ここまでメモ.md`へ出発課題、生成コース、渡す事実と素材、戻る課題、再制作しない物を書き、採用版を元の業種コースへ戻して**次の未完了コード**を続けます。編集者用の管理ファイル名は生徒ページに出しません。問を飛ばせるのは、課題コードごとの移行認定を証拠付きで残した場合だけです。

例: `SAL-01〜03 → BRDまたはWEB → SAL-04〜10`。美容コースの会社・メニュー・料金は作り直さず、生成側で整えた採用素材だけを戻します。

### 似ているコースで迷ったら

- **宿泊 `HSP`:** 客室在庫、清掃、館内、滞在中対応を扱う。**観光 `TRV`:** 複数スポット、体験事業者、地域移動、旅程を扱う。
- **製造業 `MFD`:** 受注から出荷・苦情までの工場全体を扱う。生産計画・日報・設備停止・保全の担当機能は部署別`MFG`、品質深掘りは`QA`、倉庫・配送深掘りは`SCM`へ渡す。
- **士業 `PRF`:** 外部顧客案件の受任、証拠、期限、二者レビュー、顧客報告を扱う。自社契約・社内法務は部署別`LEG`へ渡す。
- **教育 `EDU`:** 外部受講者への募集、授業、進捗、学習支援を扱う。教材自体の制作は生成`CRS`、社員の入社・独り立ちは部署別`HR`へ渡す。

## 10問は、毎回ゼロからではなく一つの作品として育っていく

各コースは、毎回ゼロから別作品を作りません。01で作った台帳や事実情報を02、03で再利用し、04〜06で画面・ツールへ育て、07以降で業務全体をつなぎます。

| 段階   | 作るもの                                                    | 新しくできるようになること                                                                 |
| ------ | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 01〜03 | 台帳、画像、提案書、説明資料、チェック票                    | AIへ正しい材料を渡し、当日から使える単品を作る                                             |
| 04〜06 | Webページ、マイページ、検索、比較、シミュレーター、運営画面 | 複数の情報と利用者を、触れる画面へまとめる                                                 |
| 07     | 受付から後工程までの引き継ぎ                                | 共通ID、承認、差戻し、失敗時処理を加える                                                   |
| 08     | 毎朝・毎週の自動更新                                        | 情報の鮮度、定期実行、通知、手動発行を扱う                                                 |
| 09     | 業種固有の安全装置                                          | 誤情報、権限外操作、漏えい、連携停止を検知し、止めて戻す                                   |
| 10     | 架空データの通し試験                                        | 受付から完了、停止・復元までを模擬し、時間、漏れ、誤り、修正回数を「教材試験値」として測る |

### 今の気分で選べる3つの進め方

- **らくらく:** 選んだ業種の01〜03を完成させる。会社や店がなくても、架空ケースの名前・画像・文章を自分好みに変えれば修了できる。
- **標準:** 01〜06を進め、単品をWebページ、マイページ、検索・比較画面、運営ツールへ育てる。
- **実務挑戦:** まず01〜10を架空データで完成させる。その後、組織が許可した場合だけ、対象者・期間・データ・停止条件を限った別の限定運用で実測する。

初心者の会社社長は、自社に近いコースの01〜03で「見せられる物」を先に作り、04以降の画面・ツールへ進むと成果を実感しやすくなります。中級ビジネスパーソンは04〜08を中心に、現在の手作業を一つの画面と定期レポートへまとめます。AI推進担当を目指す人は07〜10まで行い、承認、権限、停止、復旧、効果測定を説明できる状態を目指します。

## コードを書けなくても、AIと見本から始められる

受講生は、文章、画像、表、画面、コードを手作業でゼロから作ることを求められません。目的、材料、制約、完成条件をAIへ伝え、AIが作ったものを触り、失敗を見つけ、追加指示で直します。ただし、現実の価格、在庫、安全、契約、資格判断、顧客同意、外部送信、公開、支払は人が確認・承認します。

外部アカウント、データベース、予約・決済・通知サービスがなくても、01〜10は架空データと教材モックで完成できます。未接続なのに「予約済み」「送信済み」「決済済み」「自動運用中」と見せてはいけません。画面には未接続であることを表示し、入力、AI処理、人の承認、反映先、失敗、手動復旧までを動作モックで確認します。

| 実績バッジ     | 合格の証拠                                                                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 教材モック修了 | 架空データで画面、入出力、例外、停止・復旧を確認し、未接続箇所を明示した                                                                                       |
| 実接続検証済み | 許可済みテスト環境で、認証、権限、接続、解除、失敗時処理を確認した                                                                                             |
| 限定運用済み   | 組織承認の下で対象者、期間、データを限定し、品質、時間、費用、誤作動・ヒヤリハット・停止を記録した。重大事故がなく、問題発生時に停止・是正できたことを確認した |

## 安心して人に見せるための共通のお約束

- 実在する顧客、宿泊者、依頼者・相談者、学習者、従業員、取引先の個人情報・要配慮個人情報、営業秘密、資格業務上の秘密は原則入力しない。例外的に扱う場合は、利用目的、法的根拠または必要な同意、必要最小限化、提供先とAIサービス側での学習利用の有無、保存・削除、閲覧権限、組織承認を確認し、許可された環境だけを使う。
- 実務挑戦でも、最初は架空データを使う。承認済みの仮名化・マスキング済みデータを使う場合も、再識別や文脈からの特定があり得るため、個人情報・秘密情報ではなくなったとAIだけで判断しない。
- AIの出力は「確認済みの事実」「AIの提案」「未確認」を画面上で区別し、出典と確認日を残す。
- AI生成・合成した画像、架空の人物・店舗・料理・商品・施設・成果例は「AI生成」「教材用架空例」と表示し、実物写真、実績、顧客、施術結果として見せない。公開前に著作権、商標、肖像・パブリシティ、表示根拠を人が確認する。
- 予約、価格、在庫、契約、発注、返金、食品・施術・現場・製造の安全、資格者の見解、成績など、責任を伴う判断は人が行う。
- 本番への書込み、公開、外部送信、決済、鍵・設備の操作は初期状態で無効にし、必要な場合も人の承認、操作履歴、緊急停止、手動復帰を備える。
- 外部情報や制度は変わる。更新時刻と公式確認先を表示し、古い・取れない・矛盾する時は答えを止めて人へ引き継ぐ。

- **EDU-09｜間違った答え・偏った表現・個人情報・勝手な評価を、届く前に止めよう** — やってみること: 個人情報・成績の無断入力、AIだけの評価、誤答、偏見、不正利用、著作物の無断公開、年齢条件違反、無断連絡、心身の危機相談を正解付きケースで試す。できあがるもの: 年齢・同意確認、役割別権限、AI利用表示、講師承認、危機時の人への引継ぎ、公開ロック、AI機能の停止・手動運用への復帰・データ削除、監査履歴と安全テスト記録。〔検索・ファイル・データ・連携・試作・教材環境可・架空データ・人の確認〕
- **EDU-10｜架空の20人で、申込みから4週間の学びまで通してみよう** — やってみること: 架空学習者20人・4週間分で募集から授業準備、学習、フィードバック、報告、誤答・無断連絡時の停止と復元までを教材シナリオで通す。実在の学習者には送信しない。できあがるもの: AI学習伴走スクール、教材一式、運用ガイド、準備時間・修正率・支援漏れ・利用者評価の教材試験値、継続・改善・停止判断書。実地試験は組織許可後の別挑戦とし、同意した成人から始める。未成年者を含む場合は組織方針、年齢条件、必要な保護者への説明・同意、本人への年齢相応の説明を先に確認する。〔会話・ファイル・画像・データ・成果物・連携・試作・教材環境可・架空データ・人の確認〕

**人が必ず判断する範囲:** 教育目的、授業内容、学習評価・成績、進級・合否、指導・懲戒、個別支援、保護者等への連絡、心身の安全、教材・提出物の公開可否。

## 作った店や会社を、好きな部門・作品へ広げよう

業種別は「会社全体の一連の仕事」、部署別は「その中の担当機能」を深掘りします。先にどちらを選んでも構いません。業種作品で弱い部分が見つかったら、その部門トラックだけを追加します。

| 業種別コース       | 深掘りすると相性がよい部署別トラック                                     |
| ------------------ | ------------------------------------------------------------------------ |
| 小売・店舗運営     | 営業、マーケティング、購買・調達、経理・財務、SCM・在庫                  |
| 飲食店             | マーケティング、購買・調達、経理・財務、品質管理、カスタマーサポート     |
| 美容・サロン       | マーケティング、営業、カスタマーサクセス、経理・財務、IT                 |
| 宿泊施設           | カスタマーサポート、マーケティング、総務・施設、経理・財務、IT           |
| 観光・体験サービス | 商品・サービス企画、マーケティング、営業、カスタマーサポート、IT         |
| 建設・リフォーム   | PMO、購買・調達、品質管理、経理・財務、法務・コンプライアンス            |
| 不動産仲介・管理   | 営業、法務・コンプライアンス、経理・財務、総務・施設、マーケティング、IT |
| 製造業・工場全体   | 製造・生産管理、品質管理、SCM・物流・在庫、購買・調達、IT                |
| 士業・専門サービス | 法務・コンプライアンス、PMO、経理・財務、カスタマーサポート、IT          |
| 教育・スクール     | 商品・サービス企画、クリエイティブ、マーケティング、人材開発、IT         |

### 二つ以上の業種をつないで、大きな作品へ育てるなら

- **泊まる＋楽しむ:** 宿泊施設と観光・体験サービスを、共通旅行IDと承認済み予約情報でつなぐ「地域おもてなしポータル」。
- **探す＋直す＋住む:** 不動産と建設・リフォームを、建物ID、図面版、見積・変更承認でつなぐ「建物ライフサイクルルーム」。
- **つくる＋売る:** 製造と小売を、品番、ロット、在庫、販促、回収対象でつなぐ「商品トレーサビリティ＆販売センター」。
- **学ぶ＋働く:** 教育と選んだ業種を、教材用の架空業務、作品評価、人の指導でつなぐ「業界実習スタジオ」。

統合作品を作る時も、各業種の正本は上書きしません。それぞれの`ここまでメモ.md`から、承認済みの完成品、共通番号、データ項目、人の判断、対象外だけを新しい統合プロジェクトへ渡します。

## 本の1ページにするとき、毎回つけるもの

この初稿を精査した後、採用する各チャレンジを次の順で本文化します。

1. **今日はこれを作る:** 店、現場、事務所で今日手元に残る具体物、形式、最初の完成までの目安。
2. **使うもの・今回はどう渡す:** 材料は短文なら貼り、見た目や表が大事なら添付する。作業画面は一回ならChat、実ファイルを作って何度も直すならWorkと分けて示し、追加資料は使う前に名前と理由を示す。
3. **まずこう言ってみる:** 店や現場で実際に出そうな、短くて少し雑な最初の一言。
4. **出てきた物を実際に触る:** 開く、予約条件を見る、数字を変える等、受講者本人が行う一つの操作。
5. **出力を上げるコツ:** 「情報が古い」「例外がない」「誰が見るか分からない」時に、三つ以内から一つ選ぶ短い一言。
6. **やりがちなミス:** 古い情報、抜け、重複、してはいけない操作、止め方の忘れ。
7. **ここまでできたら完成:** 開けた、使えた、内容が合った、送信・公開前で止まれた、保存できた、から本問に必要な三条件。通常チャット・添付は本人が保存し、WorkはAIへ保存を頼んだ後に本人が開く。
8. **自分の仕事なら:** 自分の店・現場へ一か所だけ置き換える小さな応用。新しい機能や次の課題はここへ混ぜない。
9. **困ったら藤本に聞く:** 画面、課題名、使ったファイル、止まった所をまとめる短い相談メモ。
10. **ステップアップ:** 今回の完成品を正本のまま使う次の課題IDまたは総仕上げ、現場で一つの目的として便利になる内容、同じ会話へ送る短い一言。任意であり、現在の課題の合否には含めない。
