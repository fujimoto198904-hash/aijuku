# 教科書本文 執筆ガイド(章担当者用)

> 状態: 全730課題の量産用 / `docs/TEXTBOOK_TEACHING_METHOD.md`(教え方の正本)を1章の作業手順へ落としたもの
> 対象: 章単位で本文を書く執筆担当(AIエージェントを含む)とレビュー担当

## 何を書くか

1章 = 1コース10課題。正本は `lib/textbook-lessons/<track>/<章ファイル>.ts` の
`chapter.lessons`(課題IDごとの`TextbookLesson`)と`chapter.flagship`(旗艦作品)です。
型は `lib/textbook-lessons/types.ts` を読みます。コメントに各項目の意味があります。

課題の設計(タイトル・やってみること・できあがるもの・タグ)は4つの課題定義文書が正本です。
本文は必ずその設計と同じ成果を指すように書きます。定義に無い機能・人名・数字・期限・効果を足しません。

## 書き方の絶対ルール

1. **講義ではなく「一緒に一個作ってみよう」**。編集者口調・機械口調(「要件定義を実施」「〜を設定」)禁止。
2. **firstWord(まずこう言ってみる)は現場の人の雑な一言**。端折りがあり、言い切らないこともある。
   長い理想プロンプトを最初に見せない。「〜してください」の丁寧すぎる依頼文にしない。
   課題の合否や安全に関わる指示(「まだ送らないで」「まだ公開しないで」「架空データだけで」)は雑な言い方でも必ず入れる。
3. **色はカラーコードでなく「明るめ」「信頼感」「落ち着いた感じ」**のような言葉で頼む。
4. **1回で完成しない作品(Excel/PowerPoint/サイト/アプリ/定期実行等)は`nextPrompts`で刻む**。
   完成に必要な追加指示を`improvementTips`(任意のコツ)へ混ぜない。
5. **本人が触る操作(tryActions)が必ず1つ以上**。開く、押す、数字を変える、比べる、保存し直す等。
6. **mistakesはその成果物で本当に起きやすい失敗**を3〜5件。他課題の言い換えコピー禁止(機械検査で落ちる)。
7. **completionは本人の行動で確かめられる条件**を2〜4件。「開けた」「使えた」「合っていた」「止まれた」「残った」の言葉で。
   AIの「できました」を証拠にしない。
8. **送信・登録・公開・支払・契約・採用・権限変更は人の確認前で必ず止まる**。
   「申込保存」を「予約確定」と呼ばない。ローカル確認と公開を混同させない。
9. **Windows限定・Mac限定にしない**。違いがある操作だけ短く分岐。
10. **実在の会社・人物・口座・連絡先・効果実績を書かない**。数字はデモデータ内の架空数字だけ。
11. **improvementTipsは3件以内**、「一つ選べばよい」前提の短い言い方で書く。
12. **savePromptはWorkでAIに保存を頼む一言**。何を(完成品+うまくいった一言+未確認事項)、どこへ(完成フォルダ)、
    何という名前で残すかが入る。Chatでの本人保存はUI側の共通案内が出すので書かない。
13. **applicationは「一か所だけ置き換える」想像しやすい応用例**を1〜2文で。三段階の大構想を並べない。
14. **課題間で同じ文章を使い回さない**。firstWord/savePrompt/application/stepUp.sayは全730課題で一意
    (正規化一致・類似90%以上は機械検査で失敗する)。

## 材料(files / carryIn / inputMethod)

- `files`は`lib/demo-data-files.generated.json`に実在する相対パスだけ(3業種の生成元ZIP共通・156件)。
  検査で実在チェックされ、課題に割り当てた1業種の必要ファイルだけが教科書ページから直接配信される。
  存在しないファイル名を創作しない。`files`を変更したら`npm run build:demo-index`を実行する。
- 前課題の完成品を材料にする時は`carryIn`へ「SAL-01で保存した「メニュー.xlsx」を貼る」のように書く。
  この場合`files`は空でもよい(新規ファイルが不要なら増やさない)。
- 会話だけで始められる課題は`inputMethod: 'none'`+`files: []`。
- 主な開始素材: `課題/01メール.txt`〜`課題/10AI安全.txt`(短文メモ)、`課題/11会社.pdf`、`課題/12料金.pdf`、
  `課題/13組織.pdf`、`課題/14AIルール.docx`、`10_会社まるごと/`のExcel9冊、`20_Word/`の議事・電話・引継ぎ生メモ、
  `30_PDF/`の月次レポート・見積・請求・領収書・帳票、`90_OCR練習PDF/`、`99_データ辞書/`。
- 業種の違いは本文を3本複製しない。課題ごとの業種は`lib/demo-task-download-plan.generated.json`で一つに固定し、
  読者に業種選択を求めない。実在3業種(美容・建設・不動産)以外の業種章は、仕事の流れが近い代替データ(`proxy`)であることをUIで隠さない。

## 10問のリズム(章の中の成長)

| 範囲 | 役割 |
| --- | --- |
| 01〜03 | まず動く物を作る(最初の成功は早く) |
| 04〜06 | 使いやすくし、必要な情報・機能を足す |
| 07〜08 | 実際の仕事の流れへつなぐ |
| 09 | 失敗、誤り、権限、停止、戻し方を確かめる |
| 10 | 架空データで最初から最後まで通し、完成品にまとめる(コース総合) |

- 機械的に当てはめず、その章の完成物に合う自然な成長へ調整する。
- **前課題の完成品を次課題が使う**。白紙からの作り直しをさせない。何を引き継ぐかは`carryIn`か本文へ明記。
- 難易度は専門用語でなく「一回→継続」「自分→複数人」「画面→DB」「試作→止められる運用」の軸で上げる。

## stepUp(ステップアップ)と正式な次課題

- `formalNextTaskId`は**コース順の次のID**(Lv.05→Lv.06、SAL-03→SAL-04)。機械検査で強制される。
- `targetTaskId`は「今の完成品が一番自然に育つ行き先」。多くは次のIDだが、飛び先が自然なら
  同章内の先のID(例: Lv.24→Lv.28)や、隣接コース(例: SLS-05→SLD-01系)でもよい。
  カタログに実在するIDのみ。自分自身は不可。
- **コース終端(共通Lv.200と、専門コースの-10)だけ`kind: 'terminal'`**(総仕上げ)。
  それ以外の課題をterminalにすると検査で落ちる。共通のLv.10等の章末は次章の先頭へつなぐ。
- `say`は「今いるChatまたはWorkの続きで送れる短い一言」。次課題の本文を読まなくても一歩進める内容。
- `carryOver`は今回の完成品のうち何をそのまま使うか。`adds`は一つの目的として増えること。

## flagship(章の旗艦作品)

10問後に手元へ残る作品の完成イメージ。課題定義文書の章見出し(「10問後に手に入るもの」)と一致させる。

- `title`: 作品名。`summary`: 何がどう使える状態かの一文。
- `preview.kind`: `files`(完成フォルダの中身) / `screen`(画面の見どころ) / `excerpt`(成果物の抜粋) / `flow`(仕事の流れ)
  から、その作品が一番伝わる見せ方を選ぶ。
- `preview.lines`: 3〜10行。ファイル名の一覧、画面の要素、文書の抜粋等の具体行。

## トラック別の注意

- **共通(Lv.01〜200)**: 全ビジネス共通(01〜60)→作る人(61〜130)→AI推進・運用(131〜200)。
  章末課題(Lv.x0)は「章末作品」として章の成果をまとめ、次章へ引き継ぐ。Lv.200だけがterminal。
- **部署別**: その部門の担当判断・承認・上流下流を扱う。媒体制作の深掘りは生成特化へ渡す
  (`docs/TEXTBOOK_CURRICULUM_MASTER_MAP.md`のクロスウォーク表を優先)。
- **業種別**: 顧客入口→提供→引き渡し→改善の一連を再現。人が必ず判断する範囲(章末の注記)を
  09・10の安全条件へ反映する。
- **生成特化**: 実ファイル品質まで届ける。`.pptx`/`.xlsx`は「開けた・直せた・崩れない・再計算された」まで、
  画像は「実物を開いて崩れを見る」まで、ゲーム/アプリは「操作できた・残った」まで。
  文章案・画像だけでは完成にしない。GAMとAPPを無理に接続しない。

## 章を書き上げる手順

1. 課題定義文書から自章の10課題(タイトル/やってみること/できあがるもの/タグ)を読む。
2. 章の旗艦作品を一文で確認し、10問の成長(何をどの課題で引き継ぐか)を決める。
3. 各課題の本文を書く(上のルールに従う)。
4. 4つの目で読み直す: 初心者経営者(意味が分かるか、やりたいか)/中級ビジネスパーソン(明日使えるか、幼すぎないか)/
   AI推進担当志望(安全・運用・引き継ぎまで育つか)/教えるプロ(最初の成功が早いか、説明より行動が先か)。
5. `npx tsx scripts/check_textbook_lessons.ts --chapter <章キー>` を実行し、失敗0にする。
6. `npx tsc --noEmit` が通ることを確認する。

## 検査コマンド

```bash
npx tsx scripts/check_textbook_lessons.ts --chapter common-01   # 章単位
npm run build:catalog   # 章完成後にカタログ再生成
npm run check:lessons   # 全体(730件そろってから合格)
npm run build:lessons   # サンプル10文書の再生成(代表課題を触った時)
```
