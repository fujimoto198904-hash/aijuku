# スマホ下部メニューの押しやすさ

2026年9月8日。下部メニューが小さく押しにくいという報告への修正です。ローカル実装のみ。本番は版28のままで、会員データ・リンク先・公開設定は変更していません。

## 修正

- 739px以下でリンクの高さを48pxへ縮める上書きを削除。下部メニューは1項目4rem（通常64px）、横幅は均等5分割の列全体を押せます。もともとリンク全体が押せる実装であり、アイコン23pxの範囲にクリックが限定されていたという意味ではありません。
- スマホのアイコンを23pxから1.75rem（通常28px）に拡大。アイコン中心の見た目と読み上げ用ラベルを維持します。
- 押している間にリンク全体を縮めず、反応する動きはアイコンだけへ。動きを減らす設定でも背景色で反応を示します。
- 下部メニュー高を「リンク高＋上下余白＋境界線＋端末の安全余白」の共通変数に統一。本文末尾にも同じ高さ以上を予約します。
- 教科書の読書バーが共通メニューと同じ下端に重なり隠れる配置を修正。共通メニューの上へ配置し、下端の安全余白を二重に取りません。
- `viewport-fit=cover`を指定し、ヘッダー上端・本文左右・両方の下部バーの左右に端末の安全余白を反映。拡大禁止は追加していません。
- 1050px以上は従来のPCサイドバーと高さ・下余白を維持。DB・API・教材本文・新しい依存関係の変更はありません。

## 確認範囲

`check_mobile_navigation.ts`を既存UI検査へ追加。実際のCSSを解析し、320〜1049pxの幅ごとの上書き、16px/32pxのルート文字サイズ、左右・下端の安全余白、本文と読書バーの共通位置、PCへの切り替えを検査します。実ブラウザーのレイアウトエンジンではなく、宣言と計算式の契約検査です。

ホーム・見つける・Lv.137のローカルHTTP応答で、200と`viewport-fit=cover`の出力を確認。型検査、変更範囲のlint、既存の全体検証・ビルドは成功しました。スクリーンショット・スマホ実機でのタップ確認は未実施で、上記の数値はソース設定値です。
