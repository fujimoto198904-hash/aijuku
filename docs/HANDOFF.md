## 開発環境

教科書の質問導線を修復・公開済み。「質問を書く」→`/community/new?kind=question&task=ID`へ進み、一つのフォームで入力・投稿します。課題名を別タブで開け、登録・規約同意後も元の質問画面へ戻ります。本人ノートの共有は独立コピーです。

投稿画面はスマホ向けに本文を主役に再構成・公開済み。任意で写真・URLを追加し、毎回のタイトル入力と公開確認チェックを外しました。送信ボタン自体を公開操作とし、プロフィール公開・規約同意・非公開ノートの境界は維持します。画像は投稿時のみアップロード、500KB以下、会員50MB／全体2GB／1日20枚／未使用5枚まで。同時保存はD1の1文で予約し、未使用画像の回収失敗は削除待ちに記録します。0019・0020を含む公開済みです。[仕様と確認範囲](POSTING_2026_09_06.md)を参照してください。実ブラウザーの画像選択・本番での実画像保存や回収は未確認です。

教科書の記録導線も統合・公開済みです。本文と教材一覧は「マイページで記録する」→`/mypage?task=ID#learning`の一つの入口へ。課題カードからあとでやる・完了・非公開ノート・作品の追加へ進みます。作品は`#skill-record`でフォームへ移動し、同じ課題を初期選択。旧`#learning`／`#skills`と、保存済み記録は維持しています。DB・APIの保存条件、作品の運営確認、公開同意に変更はありません。

表示名・公開ユーザーID・写真の編集を一つに統合し、9月7日に本番反映済みです。仕様・互換性・確認項目は[プロフィールとID](PROFILE_IDENTITY_2026_09_06.md)。新IDでの本番登録・変更は隔離検査とは別に運用確認してください。

Node.js 22.13以上、npm lockfileを使います。`npm ci` → `npm run db:migrate:local` → `npm run doctor` → `npm run dev`。ポートは起動時に表示された値を正としてください。

0000〜0018は本番適用済みです。0016は交流機能、0017は認証アカウントに復旧コードのハッシュと更新日時、0018は公式公開データを追加しています。適用済みファイルは書き換えず、次の変更は追加してください。

0019は公開IDの一意制約・旧ID保持・変更番号・プロフィール写真参照を追加。0020は画像削除待ちを追加。両方を本番公開アーカイブに含めました。0019を読む公式プロフィール経路の本番応答は正常です。既存会員の名前・ログイン名・公開設定を自動変更しません。

## 公開状態と残りの運用確認

最新はSites版29です。[スマホ下部メニューの公開記録](RELEASE_2026_09_09_MOBILE_NAV.md)を参照してください。版28の[日常操作の改善](RELEASE_2026_09_07_USABILITY.md)、版27の[フィード・初回案内](RELEASE_2026_09_07_FEED.md)、検索の版25、スマホの基本レイアウトの版24を引き継いでいます。

デザイン調整は[AISTOCK_DESIGN.md](AISTOCK_DESIGN.md)、交流機能は[AISTOCK_SOCIAL.md](AISTOCK_SOCIAL.md)を参照。教材紹介と会員投稿を混在させ、公開プロフィール・いいね・DMを追加。個人状態を含む公開ページとDMはキャッシュ禁止です。`npm run check:ui`を通常の検証へ追加しています。定期投稿は未稼働です。

スマホの表示は739px以下で画面幅のフィード＋アイコン中心の下ナビ。フィード上部のタブ・種類フィルターは削除し、旧条件付きURLは維持。通常リンクと正式ドメインの経路を保ち、対応環境に限り短いページ切替と画面外の描画省略を行います。本文16px、主要操作44px以上、reduced-motion、公式AIのバッジを維持。メッセージの初回案内は専用の余白付きカードへ変更し、重複した空表示を避けています。

ユーザー名・パスワード登録はメール設定から独立しています。ローカルの隔離D1で登録→ログイン→復旧→再ログイン、コード再利用・同時実行・既存認証との競合・予約名・CSRF・回数制限を検証します。本番は登録・マイページ・ログアウト失効・再ログインをHTTP検証済み。実ブラウザー操作・本番復旧・2人の実会員によるDMは未確認です。Googleログインと確認メールは本番未設定・非表示です。

新規登録時に現行規約への同意を記録するため、直後の再オンボーディングは不要です。表示名・ユーザーIDは本人が設定し、プロフィールは非公開から始めます。空のマイページにフィード・初心者教材の入口を表示。`/mypage/profile`で公開とDM受信を本人が選び、保存後は元のメッセージ宛先へ戻れます。@IDを設定していない旧会員のログイン名を勝手に公開しません。メール未登録は`members.email=''`／`contact_email=NULL`で扱い、架空アドレスを作りません。メールなし会員には、現在のメール一致方式のGoogle後付け連携を表示しません。

登録時は復旧コードを発行・表示せず、すぐに元のページへ戻ります。コード保存の必須チェックもありません。必要な人だけマイページ→「ログインとアカウント」→「パスワードを忘れたときの備え（任意）」から現在のパスワードで発行します。初回発行前はハッシュと日時がNULLで、発行対象判定は発行済み判定と独立しています。新@IDでも復旧でき、旧ログイン名による復旧も維持します。

復旧コードは任意の発行時だけレスポンスに含め、DBには用途・会員ID付きHMACハッシュのみ保存。URL・ログ・localStorageには保存しません。`/account/recover`からパスワードを再設定すると、コードを交換し全既存セッションを失効します。名前だけで手動復旧せず、メールなし・復旧コードなしでパスワードを忘れた場合は復旧不可と案内します。通常の登録を軽くしても、パスワードのハッシュ保存・セッションCookie・権限・回数制限は維持します。

| 環境変数                                              | 用途                                        |
| ----------------------------------------------------- | ------------------------------------------- |
| `AUTH_GOOGLE_CLIENT_ID` / `AUTH_GOOGLE_CLIENT_SECRET` | Googleログイン用Web OAuth。Calendar用とは別 |
| `AUTH_EMAIL_API_KEY` / `AUTH_EMAIL_FROM`              | Resendの確認メールと認証済み送信元          |
| `AUTH_PASSWORD_PEPPER`                                | 既存秘密値を維持。変更は既存ログインに影響  |
| `AUTH_OWNER_MEMBER_ID` / `AUTH_OWNER_LOGIN_ID`        | 既存運営権限を維持                          |

Googleの戻り先は`https://mon-ai.jp/aistock/api/auth/google/callback`。メール登録は期限付き・一度だけ使える確認リンクから、表示名・8文字以上のパスワード・規約同意へ進みます。メール一致だけで別アカウントを自動統合しません。秘密値は実行環境にだけ設定します。

設定の存在確認だけでは、配信やログイン成功の証拠にはなりません。一般会員で登録→マイページ→投稿→保存→再ログインまで確認してください。デモの書込みは禁止です。

## 公開手順と戻し方

既存Sitesプロジェクトを再利用し、`project_id`を変更しません。D1は`DB`、R2は`MEDIA`。新規Siteは作成しません。

1. `npm run verify`。教材の生成物と既存の未コミット変更を確認。
2. 意図したソースだけコミット。無関係な変更を含まないコミットから公開用ZIPを作成。
3. 親MON-aiサイトへ`/aistock`の内部転送を追加。別プロジェクトのAGENTSを先に読む。
4. 既存Sitesへソース版を保存して公開。DB・画像・正式ドメインのリンクを確認。
5. `/aijuku`から対応する`/aistock`下層URLへ一時転送。本人登録も正式ドメインで確認。
6. Aitockの本人記録を書き出せるまで、旧Vercelドメインを一括転送しない。
