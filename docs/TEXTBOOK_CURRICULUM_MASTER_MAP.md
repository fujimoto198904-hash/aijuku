## まず「勉強」ではなく、作ってみたい未来を選ぶ

730問は、覚える順に並んだ知識の一覧ではありません。**「こんな物までAIと作れるんだ」と、自分の次の作品を見つけるメニュー**です。受講者はレベル番号だけで開始場所を決めず、タイトルを眺めて、完成した場面を一番想像できるものから選べます。

タイトルと各ページは、次の「ワクワク設計」を共通ルールにします。

1. **完成物が見える:** 「分析を学ぶ」ではなく、「今日の売れ筋がひと目で分かる店長画面を作ろう」と書く。
2. **使う場面が見える:** 朝6時、商談前、問い合わせ直後、閉店後など、使う瞬間を入れる。
3. **うれしい変化が見える:** 迷わない、すぐ答えられる、毎朝読める、一つにつながる等、完成後の変化を伝える。
4. **自分の仕事へ置き換えられる:** 架空例を示しつつ、「自社なら商品・顧客・数字のどこを替えるか」がすぐ分かるようにする。
5. **怖くない最初の一歩がある:** 最初から本番公開や自動実行を求めず、見本、架空データ、教材モックから触れる。

各チャレンジは、4冊共通で「今日はこれを作る」「使うもの」「まずこう言ってみる」「出てきた物を実際に触る」「出力を上げるコツ」「やりがちなミス」「ここまでできたら完成」「自分の仕事なら」「困ったら藤本に聞く」「ステップアップ」の順に本文化します。安全、権限、出典、公開確認も、難しい注意書きとして最後に並べません。**人に見せる前に、ここだけ見れば大丈夫**という具体的な失敗例と完成条件へ入れます。最後のステップアップは任意とし、今の完成品に便利を一つだけ足します。

## 資料の入口を、成果物より難しくしない

現場の材料は、メール本文、チャット、PDF、Word、Excel、画像、複数フォルダ等、同じ形では届きません。全730問の本文では、**材料の渡し方**と**作業画面**を分けて示します。

1. **短い文章:** 本文をコピーして、そのままチャットへ貼る。
2. **書式付き資料:** PDF、Word、Excel、画像等をチャットへ添付する。
3. **作業画面:** 単発ならChat、実ファイルを作る・同じ作品を直し続けるならWork。Workの入力欄でも、短文は貼り、書式資料は添付する。Workがない環境はChatの貼付・添付と本人による保存へ分岐し、合格条件を変えない。

AIが読めなければ、同じ方法で粘らず、Workから添付へ、添付から必要部分の貼り付けへすぐ切り替えます。スキャンは必要ページの画像でも渡せます。読めなかった資料をAIに明示させ、見えない内容を推測させません。

貼り付けと添付を一緒に使っても構いません。入力方法や作業画面は作品の品質や受講者の能力ではないため採点しません。通常チャットまたは添付で進めた成果物は、本人が返答をコピーまたはダウンロードして保存します。Workで進めた成果物はAIへ保存を頼めますが、最後は本人がファイル管理画面から開いて確認します。どの入口でも、同じ完成条件と安全確認を使います。

## 各課題の最後に置く「ステップアップ」

代表10課題から、各ページの最後に追加挑戦を一つ置きます。目的は次のページへ送ることではなく、**今回の完成品を正本のまま残し、便利を一つ増やすこと**です。

各ステップアップは、次の四項目を必須にします。

1. **次の課題ID:** `Lv.06`、`XLS-04`等。単純な連番ではなく、成果物が自然に育つ正式ルートを編集者が明示する。
2. **引き継ぐ物:** 完成ファイル、うまくいった一言、確認結果のどれを使うか。
3. **一つの目的として増えること:** 再利用、繰り返し、入力、通知、共有、安全等の目的を一つ。同じ目的に必要な関連機能は一まとまりにしてよい。
4. **続けて送る短い一言:** 次課題の本文が準備中でも、現在のChatまたはWorkから小さく試せる自然な言い方。

ステップアップは任意で、出発課題の合否には含めません。カタログの本文中に現れるIDは、前提、参考、発展先が混在するため、自動で関係を推測しません。量産時は各課題のデータへ行き先を明示し、行き先IDが730課題のカタログに存在することを検査します。コースの終点は、存在しない次番号を作らず「総仕上げ」として明示します。

## 一つの学習を立体的に組む

```text
現在の主プロジェクト（常に1つ）
├─ 技術が足りない → 共通編の開始見本・該当章を使う
├─ 担当判断を深めたい → 部署別を主プロジェクトにする
├─ 業界の仕事全体を作りたい → 業種別を主プロジェクトにする
├─ 本・画像・SNS・プレゼン・Excel・ゲーム・スマホアプリ等の作品自体が目的 → 生成特化を主プロジェクトにする
└─ 主作品の見た目・文章・ファイル品質・遊び・操作体験だけを上げたい → 生成特化を一時的な品質分岐として使う
```

たとえば「美容室の予約サイト」を学ぶ場合、三冊で同じサイトを三度作りません。

1. 業種別・美容コースで、メニュー、予約条件、施術前確認、人の判断を決める。
2. 共通Lv.71〜90の開始見本から、Webと受付の技術を借りる。
3. 見た目を深めたい時だけ、生成特化WEBまたはBRDの合格素材を持ち込む。
4. 完成した予約サイトは美容コースの正本とし、他教材側には複製せずHANDOFFだけを残す。

## 被りを消すのではなく、役割を分ける

同じ「Webサイト」「会議要約」「ダッシュボード」が複数教材に出るのは自然です。問題は、毎回ゼロから作らせることです。今後は同じ題材に次のラベルを付けます。

| ラベル       | 意味                                     | 課題文の書き方                               |
| ------------ | ---------------------------------------- | -------------------------------------------- |
| **主教材**   | その技能を初めて作り方から学ぶ           | 「設計し、作り、試す」                       |
| **応用先**   | 合格済み素材・開始見本を実務へ組み込む   | 「○○の合格版を受け取り、業務条件へ合わせる」 |
| **文脈提供** | 業種・部署固有のデータ、規則、例外を渡す | 「この業種の事実と人判断を追加する」         |
| **品質強化** | 同じ成果物の表現・媒体品質を深める       | 「正本を複製せず、採用素材をHANDOFFへ返す」  |

一つの成果物につき**正本は一つ**です。他コースは、正本を複製して別の完成品だと数えず、採用素材と変更内容をHANDOFFで返します。

## 今回の精査で反映した変更

### 1. 共通の意味を「全員必修」から「どの仕事にも転用できる基盤」へ変える

共通編は全員が200問を順番に行う教養科目ではありません。共通とは、部署・業種を問わず再利用できる**技術基盤**という意味です。介護等の特定業種は共通へ入れず、必要なら将来の業種別コースで扱います。

### 2. 共通Lv.11〜20からYouTube専用性を外す

一枚画像、配色、文字、構図、スマホ可読性、権利確認は多くの仕事に共通します。YouTube固有のサムネイル制作は生成YTB・IMGへ任せ、共通では告知画像、表紙、会議カバー、SNS画像等から選べる章にします。

### 3. 共通Lv.71〜80を会社共通のWeb制作へ寄せる

美容室は迷った時の架空ケースとして残しますが、章名と必須内容は「会社・仕事が一目で伝わるWebサイト」にします。文章・デザインの専門品質は生成WEB、予約や業種条件は業種別へ渡します。

### 4. 部署19と生成特化を分離する

部署19は、画像や文章そのものの作り方ではなく、制作依頼、素材受付、版管理、権利証跡、レビュー、承認、納品、公開結果の回収を扱います。媒体ごとの制作技法は生成特化が主教材です。

### 5. 「卒業制作」の呼び方を統一する

- 各専門10問の10番: **コース総合**。表示は「コース総合（部門）」「コース総合（業種）」「コース総合（生成）」としてもよい
- 共通の各10レベル末: **章末作品**
- 共通Lv.191〜200、とくにLv.200、および複数コース統合: **全体卒業制作**

これにより、10問を一つ終えただけで全730問修了に見える混乱を防ぎます。

### 6. プレゼンとExcelは「内容案」ではなく、開ける実ファイルまで作る

生成SLDは`SLD-03`で最初の編集可能な`.pptx`を作り、`SLD-06`で15枚＋補足5枚へ育て、`SLD-08〜10`で用途別版、PDF、発表まで仕上げます。相手は役員だけに限定せず、お客様への提案、仲間との相談、社内会議、説明会等から選びます。文章案、Markdown、画像、PDFだけでは`.pptx`完成にしません。実際のファイルをPowerPointまたは対応アプリで開き、全スライドの文字切れ、重なり、画像、書体、図表、ノート、読み順を確認し、修正版をもう一度開いて合格させます。

生成XLSは売上台帳から始め、`XLS-04`で売掛側の売上請求書下書き、`XLS-05`で買掛側の経費・支払確認候補、`XLS-06`で正式な損益計算書ではない管理用損益候補を作ります。入金予定・支払予定は損益と別表にし、`XLS-09`では過去月を差し替えず新しい行・月を追記する担当者、確認者、更新日を残します。`XLS-10`で会社用Excelパックにしますが、これは**テンプレート利用承認**までです。個別帳票は「教材用 / 発行前下書き / 個別承認済み / 正式発行済み（REV/FINの記録先）」を別管理し、テンプレート合格を個別発行の承認に読み替えません。

CSV、Web表、計算結果の文章だけでは`.xlsx`完成にしません。実際のファイルをExcelまたは対応アプリで開き、全シート、数式エラー、再計算、入力規則、表示、印刷範囲を確認し、主要値を元データ・手計算例と照合します。AIが作った税・価格・会計判断を正式値にせず、マクロ、外部接続、送信、正式発行は別承認なしに有効化しません。

XLSの値・表・グラフをSLDへ渡す標準方法は、検証済みブックからの**静的書出し**です。PowerPoint側へ元ブック名、シート名、セル範囲、基準日、版を注記し、元ブックの埋込みと外部リンクは標準禁止にします。会社が例外承認した時だけCURRENT_MANIFESTへ依存関係を残し、別フォルダ・オフラインでリンク切れを試し、配布前にはリンクを解除した版を作ります。

Officeの配布前QAでは、通常表示だけでなく、ノート、コメント、非表示スライド・シート、文書プロパティ、埋込ファイル、定義名、外部接続とキャッシュを調べ、不要情報を除いた後に再度開きます。教材・AIペルソナによる模擬レビューと、同意済みの実人テストは別実績です。レビュー区分、実人数、評価方法、確認できたこと、未検証事項を記録し、AIペルソナだけを「実人テスト済み」と数えません。

### 7. 変わりやすいChatGPT機能を固定要件にしない

ChatGPTの利用可能な機能、接続、生成形式、定期実行、公開方法は、プラン・地域・時期で変わります。教材では「2026年9月時点で必ず使える」と断定せず、課題開始時に利用画面と[ChatGPT公式の活用例](https://learn.chatgpt.com/use-cases)を確認し、利用できない時は教材モックで同じ学習目的を達成します。

## 共通の引き継ぎパック

教材をまたぐ時はチャット全文を渡さず、次の8点だけを渡します。

1. `PROJECT_BRIEF`: 誰の何を作るか、対象外、人の判断。
2. **現在の合格版本体**: 実際に開けるファイル、URL、画像等。
3. `FACTS`: 会社、商品、料金、人物等の承認済み事実。
4. `SOURCES`: 出所、確認日、利用箇所。
5. `CURRENT_MANIFEST`: 必要ファイル、版、開き方、未接続。プレゼン・Excelはファイル形式、検証アプリ、全ページ・全シート確認、再計算・印刷、Office漏えい検査、静的書出し元、リンク依存、テンプレート・個別発行状態を、ゲーム・アプリは対応OS、検証端末、ビルド版、署名・権限・導入状態も含む。
6. `HANDOFF`: 完了、未完了、変えてよい点、次の一手。
7. **安全・公開状態**: モック、実ファイル、ブラウザ、シミュレーター、本人実機、限定公開、本番運用のどこまで確認したか。教材・AIペルソナによる模擬レビューと実人テストは分け、実人数、評価方法、未検証事項を残す。
8. `OUTPUT_INDEX`: 成果物種別、正本プロジェクト、課題コード、版、場所、権利、公開状態。

教材間の分岐では、この8点の参照を`CROSS_TRACK_HANDOFF.md`へまとめます。正本は出発側主プロジェクトの`05_HANDOFF/`に置き、到着側は版付き参照またはコピーだけを持ちます。統合を始める場合は統合プロジェクトが現在の主になり、構成元の各正本は読取専用の参照元になります。

生成特化から業務コースへ戻す場合は、素材の権利・AI生成表示・サイズ・代替テキストも含めます。業務コースから生成特化へ渡す場合は、制作者に決めさせてはいけない料金、性能、承認済み表現、禁止表現を含めます。

## 今後、新しい問題を追加する時の重複判定

新しい問題は、次の順で判定します。

1. 完成品を一文で書く。知識確認だけなら、見せられる制作物へ変える。
2. 既存730問から、同じ名詞ではなく「同じ技能と同じ完成品」を検索する。
3. 既存問が主教材なら、新問は削除するか「合格版を受け取る応用問」へ変える。
4. 部署・業種固有の人判断、データ、例外、KPIのどれも追加されないなら、専門コースへ入れない。
5. 生成特化へ入れる場合、媒体・体験固有の構成、編集、操作、品質、権利、公開・導入条件を最低一つ追加する。
6. 10番が単品寄せ集めなら、01〜09を一つの操作・体験へ統合する。
7. 正本、入力元、引き継ぎ先、未接続状態を明記する。

## 編集時の採用基準

- タイトルだけで「何を作るか」「いつ使うか」「何がうれしくなるか」のうち二つ以上が想像できる。
- 「理解・整理・分析・管理・設計・最適化」だけをゴールにせず、読者が開いたり、触ったり、人へ見せたりできる完成物へ変える。
- タイトルは命令口調や試験口調を避け、「作ろう」「届けよう」「試してみよう」「完成させよう」等、隣で一緒に作る言葉にする。
- 60秒で完成場面を話せないタイトル、仕事での使い道を一例も言えないタイトルは採用しない。
- 前問の成果を次問で再利用し、毎回白紙へ戻らない。
- 初心者が01〜03で小さな達成を得られる。
- 04〜08で機能・反復・連携が増え、09で失敗を止め、10で実際に通して試す。
- AIが候補を作る部分と、人が事実・権利・公開・契約等を決める部分が分かれる。
- モック、生成済み、接続済み、限定運用、本番公開を証拠付きで区別する。
- 類似課題がある場合は、削除理由または再利用関係を説明できる。

この全体地図を、今後の課題追加・削除・教材本文化における交通整理の正本とします。個別の730問は候補を残しつつ、どの教材が主役かをこの基準で揃えます。
