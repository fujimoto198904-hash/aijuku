> 位置づけ: 文章、画像、映像、音声、Web、プレゼン、表計算、教材、ゲーム、スマホアプリを「作品・体験」として完成させる選択コース

全教材の役割、重複時の正本、コース間の乗換え方は、[カリキュラム全体地図](./TEXTBOOK_CURRICULUM_MASTER_MAP.md)を先に確認してください。

## 勉強する前に、作りたい未来を選ぼう

**「AIを勉強しよう」から始めなくて大丈夫です。まずは、完成したら誰に見せたいか、仕事のどこで使いたいかを想像して、いちばん心が動く作品を一つ選びましょう。**

本ができれば、自分の経験をお客様へ届けられます。画像ができれば、商品や企画の魅力を一目で伝えられます。ゲームやアプリが動けば、「AIでここまで作れた」という体験そのものが次の仕事のアイデアになります。各タイトルは、学ぶ用語ではなく、**その日に持ち帰れる完成形**から選べるようにしています。

この生成特化230問は、[共通200チャレンジ](./TEXTBOOK_PROBLEM_BANK_200_DRAFT.md)、[主要20部門×10チャレンジ](./TEXTBOOK_DEPARTMENT_TRACKS_200_DRAFT.md)、[業種別10コース×10チャレンジ](./TEXTBOOK_INDUSTRY_TRACKS_100_DRAFT.md)の後に、全員が追加レベルとして順番に解くものではありません。本、Instagram、画像、動画、プレゼン、Excel、ゲーム、スマホアプリなど、今作りたい1タイプを選び、10問で一つの代表作品を育てる**選択制の制作スタジオ**です。1コースだけでも修了できます。

保存場所、ChatGPTのプロジェクトとチャットの分け方、次の課題への引き継ぎ方は、[学習構造案](./TEXTBOOK_LEARNING_STRUCTURE_DRAFT.md)を使います。生成特化では「選んだ1タイプ＝1制作プロジェクト」が基本です。ただし、01〜10を一本の長いチャットにせず、`01〜03`、`04〜06`、`07〜10`の制作工程ごとに分けます。企画、採用素材、修正理由、公開条件は、最新の完成品と`ここまでメモ.md`で次のチャットへ渡します。

### 素材は、作品に合ういちばん簡単な形で渡す

素材が短い原稿や箇条書きなら本文をコピーして貼り、PDF、Word、Excel、画像、音声等の書式・見た目・中身を保つ必要があれば添付します。両方を一つの課題で使っても構いません。単発ならChat、実ファイルを作る・複数素材と前作を使って同じ作品を育てる時はWorkをすすめます。Workの入力欄でも同じ貼付・添付を使います。

AIが素材を読めなければ、フォルダ参照のまま粘らず、同じChatまたはWorkの入力欄へファイルを添付し、それでもだめなら必要部分の貼り付けや必要ページの画像へ切り替えます。Workが表示されない場合は、Chatへの貼付・添付と本人による保存で同じ完成条件へ進みます。読めなかった素材名をAIに言わせます。入力方法は作品の採点対象にしません。Chatの成果物は本人がコピーまたはダウンロードして保存し、Workの成果物はAIへ保存を頼んだ後に本人が開きます。

### このスタジオで作るところ・引き継ぐところ

- **担当する:** 作品・体験固有の構成、文章、デザイン、編集、インタラクション、操作感、端末適応、形式、権利、アクセシビリティ、ビルド・公開品質。
- **担当しない:** DB、認証、承認業務、正式な経理処理、部署KPI、業種全体の運営システム、会社端末への配布統制を作り直すこと。
- **業務コースから受け取る:** 対象者、目的、確認済み事実、料金・性能、禁止表現、承認者、公開条件。
- **業務コースへ返す:** 採用作品、版、権利・AI生成表示、サイズ・形式、代替テキスト、対応端末・ビルド版、公開・インストール状態。

### すでに作ったものは、上手に引き継ごう

各問の開始時に「できたもの一覧」を確認し、同等成果物がすでに合格していれば、次のいずれかを人が選びます。編集者が使う管理ファイル名やコードは、初心者向けの課題ページには出しません。

1. **移行認定（合格相当）:** 本問の全完成条件を満たす既存成果物だけを、実ファイルと証拠を確認して認定する。入力素材として使えるだけなら差分改善を選ぶ。
2. **差分改善:** 本コース固有の不足だけを直す。
3. **新規制作:** 同等成果物がない時だけ新しく作る。

部署・業種の標準分岐点である03・06、または[全体地図のコード単位クロスウォーク](./TEXTBOOK_CURRICULUM_MASTER_MAP.md#高重複コースのコード単位クロスウォーク)で指定された出発課題から途中分岐しても構いません。`ここまでメモ.md`に出発課題、**次の未完了課題である戻り先**、再制作しない成果物を記録し、生成コースで完成した採用版を元の主プロジェクトへ返します。会社・商品・顧客設定を別物として作り直さず、同じ案件名と成果物を使います。編集者用の管理ファイル名は生徒ページに出しません。元コースの問を飛ばせるのは、飛ばす各課題に移行認定（合格相当）の証拠がある場合だけです。

## 10問進むたび、作品が目に見えて育っていく

各コースの01〜10は、ばらばらのプロンプト練習ではありません。01で決めた相手と目的、02で作った設計、03で合格させた試作品を、04以降でも再利用します。

| 段階 | 育てるもの                                     | 次にできるようになること                                 |
| ---- | ---------------------------------------------- | -------------------------------------------------------- |
| 01   | 目的・相手・完成条件が見える企画カード         | 「何でも作る」から、誰の何を変える作品かへ絞る           |
| 02   | 構成、世界観、トーン、デザイン規則             | 好みを、AIが再利用できる具体的な制作ルールへ変える       |
| 03   | 小さく見せられる試作品                         | 全量生成の前に、品質基準と直し方を一つ決める             |
| 04   | 本文、投稿、画面、台本等の本制作               | 長い作品でも事実、人物、論理、見た目をつなげる           |
| 05   | 表紙、画像、図表、音、レイアウト等の表現       | 文章だけでなく、複数形式を一つの体験へ統合する           |
| 06   | 編集、校正、一貫性、アクセシビリティ           | 作った本人以外が迷う点、読めない点、聞けない点を直す     |
| 07   | 別媒体・別尺・別対象への展開                   | 同じ核を保ちながら、媒体に合わせて作り替える             |
| 08   | シリーズ化、テンプレート化、更新手順           | 一回の成功を、品質を落とさず繰り返せる制作方式にする     |
| 09   | 権利、事実、個人情報、表示、媒体ルール         | 出せる作品と、止めるべき作品を人が判断できるようにする   |
| 10   | 最終パッケージ、公開前確認、限定公開、振り返り | 「生成した」ではなく、証拠付きで完成・公開状態を説明する |

各タイプの10番は、その10問を統合する**コース総合**です。複数タイプをつなぐGX作品だけを生成分野の**全体卒業制作**と呼び、1コース修了と全教材修了を混同しません。

ゲームとスマホアプリは、上表を「構想→動く最小版→機能・素材統合→端末適応→再現可能なビルド→安全試験→限定運用」と読み替えます。コードが生成されたことと、実際にビルドできたこと、ブラウザで遊べたこと、シミュレーターで動いたこと、自分の実機へ入ったこと、第三者へ配布・公開したことを同じ完成状態にしません。

### 今の気分で選べる3つの進め方

- **らくらく:** 選んだタイプの01〜03。教材の架空テーマを自分好みに変え、短い試作品まで完成させる。
- **標準:** 01〜06。試作品を本編へ育て、編集、見た目、読みやすさまで整える。
- **クリエイター実践:** 01〜10。別媒体への展開、再現できる制作手順、安全確認、公開準備、効果測定まで行う。

APPでPWAまたはプレビューから始める場合、そのまま進められるのは`APP-05`までです。`APP-06〜10`で実機導入と実運用を学ぶには、ネイティブ対応スターターへ移行し、iPhoneならMac・Xcode、AndroidならAndroid開発環境を用意します。移行しない場合はPWA・プレビューの現状に応じた実績で終了し、実機導入済みにしません。

## AIと一緒に作る時の「できた！」の数え方

この教材での「AIのみ」は、受講者が文章、画像、音声、動画、レイアウト、コードを一から手作業することを必須にしない、という意味です。受講者は、目的と材料を渡し、候補を選び、事実・権利・安全を確認し、AIへ修正を指示します。開発ツールの導入、端末の信頼、Developer Mode、署名、権限許可、実機テストは本人が確認して操作します。採用、公開、広告出稿、外部送信、権利許諾、人物の同意もAIへ委ねません。

ChatGPTや接続ツールで使える生成機能は、プラン、地域、アカウント、時期により異なります。編集可能なPowerPointやスプレッドシートを作成・更新できる環境では、実際の`.pptx`・`.xlsx`を作り、対応アプリで開いてから完成判定します。動画・音声・音楽・スライド・表計算等を直接ファイル生成できない環境でも、完成台本、絵コンテ、素材、字幕、編集指示、レイアウト見本、数式設計、公開文までそろえば**制作モック修了**にできます。ただし、実ファイルを生成・再生・公開していないのに「PowerPoint完成」「Excel完成」「動画完成」「配信済み」とは記録しません。

| 実績バッジ               | 合格の証拠                                                                                                                                                  |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **制作モック修了**       | 企画、本文・台本、必要素材、構成、完成見本、確認表がそろい、未生成・未接続・未公開箇所を明示した                                                            |
| **最終ファイル検証済み** | 実際のPDF、画像、動画、音声、PowerPoint、Excel、Web、ゲームビルド、アプリビルド等を対応アプリで開き、欠落、文字、音、表示、数式、リンク、主要操作を確認した |
| **実機動作検証済み**     | 対象端末、OS、ビルド版、署名状態を記録し、実機で起動、主要操作、保存、権限拒否、再起動後の状態を確認した。ストア公開済みとは扱わない                        |
| **自端末限定運用済み**   | 自分の端末だけで複数日使い、更新、バックアップ、復旧、削除を確認した。第三者配布や一般公開とは扱わない                                                      |
| **限定公開検証済み**     | 人の承認後、限定・非公開・テスト配布等で第三者が閲覧でき、表示、導線、解除方法を確認した                                                                    |
| **公開運用済み**         | 公開先の実画面、公開日時、表示、反応、修正・停止履歴を記録した。公開ボタンを押しただけでは合格にしない                                                      |

## 安心して人に見せるための共通のお約束

- 実在しない体験、レビュー、推薦、受賞、売上、導入社、読者数、調査結果、ニュース、引用、専門家コメントを作らない。教材用の架空例は「架空」「AI生成」と表示する。
- 外部事実、数字、引用、制度を使う時は、AIの記憶だけで確定せず、元資料、URL、確認日、引用範囲、加工内容を記録する。出典が見つからない主張は削るか未確認と示す。
- 実在の作家、漫画家、イラストレーター、写真家、音楽家、映像作家等の名前を「その人そっくりに作る」指示へ使わない。線、色、光、構図、テンポ、語彙等の観察可能な特徴へ分解し、第三者作品の創作的表現を再現していないか人が確認する。
- 学習用を含め、他人の文章、画像、音源、映像、ロゴ、キャラクター、商品写真を無断で素材化しない。権利者、ライセンス、利用範囲、改変可否、クレジット条件を「元資料の一覧」へ残す。
- 実在人物の顔、声、名前、発言、推薦、私生活を本人の許可なく生成・合成しない。特に、本人が言っていない言葉、商品推薦、政治的主張、事件・災害の架空映像を現実のように見せない。
- 個人情報、顧客情報、未公開原稿、社内秘密を、許可のないAI環境へ入力しない。必要な場合は架空化・最小化し、会社規則、利用目的、保存・学習利用、削除、権限を確認する。
- 広告、提供、アフィリエイト、贈答等の関係を隠さない。効果、比較、No.1、最安、必ず成功等の表示には、公開時点で確認できる合理的な根拠を用意する。
- AI生成・合成が見る人の判断に影響する場合は、その事実を分かる位置へ表示し、公開先の最新ルールも確認する。表示しても、なりすましや権利侵害が許されるわけではない。
- 画像には目的に合う代替テキスト、動画には重要な音を含む字幕または同等情報、音声には文字起こし、資料には見出し構造と十分なコントラストを用意する。
- 最終公開、印刷発注、広告出稿、メール配信、SNS投稿は必ず人が内容と対象を確認して実行する。教材内の自動化は、下書き生成と公開待ちキューまでを標準にする。
- AIが作ったコードも、依存ライブラリ、ライセンス、外部通信、権限、秘密情報、ビルド結果を人が確認する。Apple Accountのパスワード、証明書の秘密鍵、Android keystore、署名用パスワード、APIキーをAI入力、Git、提出物へ含めない。
- 採用版、元資料、使った一言、修正理由、生成日、利用モデル、権利・事実確認、公開状態を「できたもの一覧」へ残す。生成できた証拠と、公開できた証拠を分ける。

## 01｜本・電子書籍 — 自分の経験が「読まれる一冊」になる

> 10問後に手に入るもの: 自分の経験や専門知識を体系化した「8章構成の実用書」

- **BOK-01｜思わず手に取りたくなる、本のタイトルと帯を作ってみよう** — **やってみること:** 自分の経験や専門分野から、想定読者、悩み、読後の変化、この本だけの視点、扱わない範囲を決める。**できあがるもの:** 仮タイトル10案、帯コピー3案、読者像、1枚企画書。〔企画・成果物・人が確認〕
- **BOK-02｜読み始めたら迷わない、8章の目次を作ってみよう** — **やってみること:** 読者が「悩みの理解→解決→実践→定着」と進める8章を作り、各章の問い、具体例、演習を設計する。**できあがるもの:** 詳細目次、章のつながり図、ページ配分表。〔構成・成果物・人が確認〕
- **BOK-03｜まずは第1章。3,000字の「読める原稿」にしてみよう** — **やってみること:** 経験、架空事例、手順、まとめ、読者ワークを含む第1章を書き、難語や説明不足を直す。**できあがるもの:** 3,000〜5,000字の試作章、初稿・改稿比較表、読者チェック票。〔文章・試作・人が確認〕

- **XLS-08｜売上から支払まで5つの表を、一つの会社用Excelにまとめよう** — **やってみること:** 5表の合格版を、元シートを残したまま一つのブックへ統合し、管理用損益候補と入出金・資金予定のサマリーへつなぐ。列名、日付、単位、重複、欠損をそろえ、集計元をたどれるようにする。プレゼンへは図表を静止状態で渡し、元ブック、シート、セル範囲、基準日、版を記録する。**できあがるもの:** 編集可能な`会社数字統合.xlsx`、元データ5表、損益・資金・予実サマリー、重複・欠損一覧、PowerPointへの受渡しメモ。〔複数表統合・追跡可能性・人が確認〕

- **XLS-10｜見積書から月次会議まで使える、会社用Excel一式を完成させよう** — **やってみること:** 見積、請求・売掛、経費・買掛・支払予定、管理用損益候補・資金予定、予実、統合サマリーの採用版を`.xlsx`で整理し、命名、版、入力責任者、確認者、更新日、バックアップをそろえる。全ファイル・全シートを開き、数式、入力規則、グラフ、印刷に加え、ノート、コメント、非表示シート・行・列、定義名、文書プロパティ、埋込み、外部リンク・接続を検査する。不具合は編集用正本へ戻して直し、不要情報と依存を除いた配布用コピーを分ける。承認リンクを残す場合は依存先と確認日を記録し、リンク切れを試す。正式発行、会計・税務判断、支払は行わない。**できあがるもの:** 編集可能な会社用Excelパック`.xlsx`、編集用正本、配布用コピー、全シート表示・漏えいQA、数式照合表、更新・復旧手順、利用開始判断書。〔コース総合・漏えい検査・人が利用判断〕

## どのページも「見本→一緒に作る→応用」の順で進む

この文書は230問の候補と成長順を決める設計図です。採用した各チャレンジを次の順で本文化します。

1. **今日はこれを作る:** 今日手元に残るページ、画像、音声、動画、PowerPoint、Excel、ゲーム、アプリ等の具体物と形式。
2. **使うもの・今回はどう渡す:** 材料は短文なら貼り、見た目や表が大事なら添付する。作業画面は一回ならChat、実ファイルを作って何度も直すならWorkと分けて示し、前作や素材を使うなら先に名前と理由を示す。
3. **まずこう言ってみる:** 作りたい物を普段の言葉で頼む、短くて少し雑な最初の一言。
4. **出てきた物を実際に触る:** ファイルを開く、再生する、文字を直す、数値を変える、ボタンを押す等の一操作。
5. **出力を上げるコツ:** 画像、動画、文章、PowerPoint、Excel等を良くする三つ以内の一言から、一つだけ選ぶ。
6. **やりがちなミス:** ファイル不足、文字切れ、数式違い、出典・権利漏れ、まだ作っていない物を完成扱いする失敗。
7. **ここまでできたら完成:** 開けた、体験できた、内容・権利が合った、公開前で止まれた、保存できた、から本問に必要な三条件。通常チャット・添付は本人が保存し、WorkはAIへ保存を頼んだ後に本人が開く。
8. **自分の仕事なら:** 自分の作品へ一か所だけ置き換える小さな応用。新しい機能や次の課題はここへ混ぜない。
9. **困ったら藤本に聞く:** 画面、課題名、使ったファイル、止まった所をまとめる短い相談メモ。
10. **ステップアップ:** 今回の作品を正本のまま使う次の課題IDまたは総仕上げ、表現や機能を一つの目的として足す内容、同じ会話へ送る短い一言。任意であり、現在の課題の合否には含めない。

## 自分の作品がどこまで育ったか、8つのものさしで見よう

各観点を0〜2点、合計16点で採点します。12点以上かつ「事実・権利・公開状態」で0点がなければ合格候補です。点数だけで公開を自動決定しません。

| 観点             | 0点                  | 1点                      | 2点                                                          |
| ---------------- | -------------------- | ------------------------ | ------------------------------------------------------------ |
| 相手と目的       | 誰向けか不明         | 相手か目的の片方が曖昧   | 相手、変化、利用場面が具体的                                 |
| 作品としての完成 | 部品だけ             | 一応見られるが欠落あり   | 指定形式で開き、最初から最後まで体験できる                   |
| 独自性           | 一般論・量産         | 自分の材料が一部ある     | 経験、判断、構成、世界観が一貫する                           |
| 伝わりやすさ     | 読めない・聞けない   | 一部迷う                 | 構成、文字、音、導線が対象に合う                             |
| 事実と透明性     | 根拠なし・架空を偽装 | 出典や表示が一部不足     | 事実、創作、推論、AI生成、広告が区別される                   |
| 権利・同意       | 出所不明・無許諾     | 確認待ちが残る           | 出所、許諾、利用条件、同意、生成履歴が記録される             |
| 再現性           | 作者しか直せない     | 手順が部分的             | テンプレート、命名、版、引継ぎで再制作できる                 |
| 公開状態         | 状態を誤表示         | 未公開等は示すが証拠不足 | モック、最終ファイル、限定公開、本番公開を証拠付きで区別する |
