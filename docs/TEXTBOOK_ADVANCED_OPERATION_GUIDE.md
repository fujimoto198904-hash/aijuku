>

## この文書を使う人

この文書は、Lv.61以降で複数の作品・システムを長く育てる受講者と講師のための資料です。`PROJECT_BRIEF`、`ROUTE_CARD`、`CURRENT_MANIFEST`、`HANDOFF`等を扱います。初めて受講する人は、この先を読まず、[初心者向けのはじめ方](./TEXTBOOK_LEARNING_STRUCTURE_DRAFT.md)を使います。

ここから先には、複数システムを長く育てる時の正本、安全、版、費用、引継ぎの詳しい方法をまとめます。会社の規則や講師の指示に合わせ、必要になった部分だけ使います。

教材全体の役割、重複時の正本、コースの主従関係は、[カリキュラム全体地図](./TEXTBOOK_CURRICULUM_MASTER_MAP.md)を正本とします。

[共通200チャレンジ](./TEXTBOOK_PROBLEM_BANK_200_DRAFT.md)、[主要20部門×10チャレンジ](./TEXTBOOK_DEPARTMENT_TRACKS_200_DRAFT.md)、[業種別10コース×10チャレンジ](./TEXTBOOK_INDUSTRY_TRACKS_100_DRAFT.md)、[生成特化23タイプ×10チャレンジ](./TEXTBOOK_GENERATION_TRACKS_200_DRAFT.md)をまたいで本格的な作品を育てる場合も、現在動かす中心作品は一つにします。素材は使い回し、同じ物を別教材で作り直しません。

### 作りたいものを、フォルダ・プロジェクト・チャットで育てる

| 層 | 数 | 役割 |
|---|---:|---|
| 親練習フォルダ | 受講者ごとに1つ | 全ファイル、進捗、証拠、引き継ぎを手元に残す |
| 共通作品プロジェクト | 最大5つ | 共通編で同じ作品を複数章にわたって育て、入力や部品を再利用する |
| 共通作業チャット | 必要になった分だけ | 同じ作品を数レベルずつ育て、章の切れ目や会話が長くなった所で引き継ぐ作業場 |
| 共通チャレンジ | Lv.01–200 | 1レベルごとに、触れる・見せられる完成物を一つ増やす |
| 選択専門プロジェクト | 選んだ部門・業種・生成タイプごとに1つ | 選択した10問で、一つの完成作品を育てる |
| 専門工程チャット | 選んだコースごとに原則3つ | 01〜03の準備・試作、04〜06の制作、07〜10の確認・完成に分けて引き継ぐ |

「フォルダ」は成果物の正本、「プロジェクト」は同じ作品の背景と資料を共有する場所、「チャット」は一つの工程へ集中する作業場です。AIの画面だけを保管場所にせず、採用した成果物と記録は親練習フォルダへ保存します。

ここでいう「作品プロジェクト」は、推奨構成ではChatGPTのProjectsを一つずつ作る意味です。関連するチャット、参照ファイル、プロジェクト専用の指示をまとめられる場合に使います。利用可能な機能とファイル数等はプラン・時期で異なるため、受講時点の実画面と[ChatGPT Learn](https://learn.chatgpt.com/)を確認します。Projectsを使わない場合も、同名の手元フォルダと工程ごとのチャットで同じ運用を再現できます。

共通200を最後まで進める場合も、チャット数を先に固定しません。最初は「00_START」、選んだ1プロジェクト、現在の1作業チャットだけを作ります。会話が長くなった時、作業工程が変わる時、または章をまたぐ時に、引き継ぎ4点セットを使って次のチャットを追加します。部署別から始める人は選んだDプロジェクト、業種別ならIプロジェクト、生成特化ならGプロジェクトから始められ、P01〜P05は不要です。

#### 手元フォルダとChatGPTを同期したつもりにしない

親練習フォルダを作っただけでは、ChatGPTが中身を自動で読めるとは限りません。ChatGPTのProjectsを使う場合は、その章で必要な合格版、PROJECT_BRIEF、HANDOFF、CURRENT_MANIFESTをファイルまたは利用可能な接続元として追加し、実際に参照できるか確認します。通常チャットだけを使う場合も、今回必要な最小ファイルを添付します。ファイル名を伝えただけでAIが読めたものとして扱いません。

開始時にROUTE_CARDへ、次のどれで進めるかを記録します。

| 利用方式 | 手元の正本 | AIへ渡す方法 |
|---|---|---|
| ChatGPT Projects＋手元フォルダ（推奨） | 親練習フォルダ | プロジェクトの参照資料へ必要な最新版を追加し、章初めに読めるか確認する |
| 通常チャット＋手元フォルダ | 親練習フォルダ | 新しい工程のチャットへ引き継ぎ4点セットだけを添付する |
| 会社承認済みの共有保管場所 | 承認された共有場所 | 利用可能な接続方法で追加し、権限と更新状態を確認する |

初めて作品を作る時の「初回セット」は、PROJECT_BRIEF、開始見本、今回必要な入力の3点です。前章から続ける時の「引き継ぎ4点セット」は、PROJECT_BRIEF、HANDOFF、CURRENT_MANIFEST、現在の合格版本体です。P04・P05のWeb作品では、画面の説明だけでなく、動かすファイル一式、起動・確認方法、データ項目、最小テストデータも含めます。SLD・XLSでは、画像や文章の見本だけでなく、実際の`.pptx`・`.xlsx`、開いたアプリ、表示・数式・印刷の確認記録も合格版へ含めます。

~~~text
受講者の親練習フォルダ
├─ P01 作品プロジェクト
│  ├─ C01チャット: Lv.01–10
│  └─ C02チャット: Lv.11–20
├─ P02 作品プロジェクト
│  ├─ C03チャット: Lv.21–30
│  └─ C04チャット: Lv.31–40
├─ P03 作品プロジェクト
│  ├─ C05チャット: Lv.41–50
│  └─ C06チャット: Lv.51–60
├─ P04 作品プロジェクト
│  └─ C07〜C13チャット: Lv.61–130
└─ P05 作品プロジェクト
   └─ C14〜C20チャット: Lv.131–200
~~~

### 5つの長期学習プロジェクト

| ID | 対象レベル | 育てる作品 | 難しさが増える点 | 工程ごとのチャット |
|---|---:|---|---|---|
| P01 | Lv.01–20 | 自分と事業を伝えるAI秘書、プロフィール、一枚画像、発信スターターキット | 一つの回答から、再利用できる一式へ | C01 AI秘書 / C02 一枚画像 |
| P02 | Lv.21–40 | 自分新聞、会議・電話から作る議事録、ToDo、予定、フォロー | 一回の作成から、毎日・毎回続く仕事へ | C03 自分新聞 / C04 会議秘書 |
| P03 | Lv.41–60 | 根拠付き会社資料室、業務データ30件から作る数字ダッシュボード | 一つの資料から、複数資料・表・根拠へ | C05 会社資料室 / C06 数字 |
| P04 | Lv.61–130 | 同じ練習事業を、仕事ルーティン、会社HP、受付、計算、共有DB、マイページ、選択コミュニティへ育てる | 一人・端末内から、顧客・複数利用者・共有データへ | C07〜C13 |
| P05 | Lv.131–200 | 一つの業務システムを、承認、外部連携、AI窓口、部門横断、安全、限定運用、全体卒業制作へ育てる | 動く試作から、組織で止め・戻し・運用できる状態へ | C14〜C20 |

P04とP05では、章ごとに別アプリをゼロから作り直すのではなく、同じ作品へ機能を足します。同じプロジェクト内の画像、文章、画面、テストデータ、判断記録、前章の出力を再利用します。方向を変えたい場合は、合格済み版を残して複製した枝で試します。

P04では、Lv.61〜70の仕事ルーティンをLv.71以降も管理者・スタッフ用部品として残します。Lv.71〜80で同じ練習事業の公開サイトを加え、Lv.81〜100で受付と計算、Lv.101〜110で端末保存を共有DBへ移し、Lv.111〜120で利用者別画面を加えます。Lv.121〜130の会話機能が不要なら飛ばせます。

~~~text
Lv.61–70 仕事ルーティン（管理側の最初の部品）
      ↓ 同じ事業名・色・項目を再利用
Lv.71–80 公開会社サイト
      ↓
Lv.81–100 受付・計算
      ↓ 端末保存から共有へ移行
Lv.101–120 共有DB・ログイン・マイページ
      ↓ 必要な場合だけ
Lv.121–130 チーム・会員コミュニティ
~~~

### 5学習プロジェクトを一つの物語へつなぐ

受講開始時に「練習事業テーマ」を一つ決めます。自分の事業を使えない、または迷う場合は、架空の美容室を標準テーマにします。会社名、利用者、商品・サービス、問い合わせ例、数字は架空データで統一し、途中で毎回作り直しません。

| 前半で作るもの | 後半での再利用先 |
|---|---|
| P01のプロフィール、発信素材、一枚画像、文章の調子 | P04の会社HP、問い合わせ・依頼受付、マイページの共通素材 |
| P02の業界新聞、会議・電話の議事録、ToDo、予定 | P05の定期通知、受付、承認、部門横断ワークフロー |
| P03の会社資料、根拠、FAQ、経費データ、グラフ | P04の検索・DB・計算機能、P05のAI窓口と経営画面 |
| P04の顧客画面、受付、計算、DB、ログイン | P05の承認、外部連携、監視、限定運用の土台 |
| P05の運用記録、安全機能、効果測定 | Lv.191–200の全体卒業制作と第三者への引き継ぎ |

~~~text
P01 AI秘書・発信素材 ─┐
P02 日常業務 ─┼─→ P04 顧客が使うWebサービス ─→ P05 会社が運用するAI業務システム ─→ 全体卒業制作
P03 資料・数字 ┘
~~~

P04を始める時は、P01〜P03の合格版から必要な素材だけを「P04開始パック」へ複製します。P05ではP04の最後の合格版を複製し、同じコード一式・データ項目・テスト利用者を土台にします。前の作品を直接上書きせず、各プロジェクトの合格版を残すため、途中から参加する人や別テーマへ進む人も扱えます。

このつながりは必須の順路ではありません。Lv.61から始める人には、講師が同じ構成のP04開始パックを渡します。つまり、前章を学んだ人は自作品を再利用し、途中参加者は完成見本から開始できます。

P04開始時は、利用者、中心課題、主要画面、共通ID、データ項目、権限、対象外を「SERVICE_BLUEPRINT.md」へ固定します。Lv.130では「P04_TO_P05_HANDOFF.md」を作り、P04の合格版、起動方法、データ定義、利用者と権限、テスト利用者、既知の制約、回帰テストをまとめます。P05で別作品を始める場合だけ、変える理由と新しい開始見本をDECISIONSへ残します。

### 主プロジェクトと品質分岐

教材をまたぐ時は、四つの教材を並行受講するのではなく、主従を決めます。

| 状態 | 数の目安 | 役割 |
|---|---:|---|
| **主プロジェクト** | 常に1 | 現在の完成品の正本。合格と進捗を判定する場所 |
| **品質分岐プロジェクト** | 必要な時だけ1 | Web、画像、広告、教材等の不足品質を直し、採用版を主へ返す場所 |
| **統合プロジェクト** | 統合時だけ1 | 二つ以上の合格済みコースをつなぐ場所。開始した時点で現在の主プロジェクトになり、各構成プロジェクトは読取専用の正本として残す |

同時に編集する上限は「現在の主プロジェクト1＋品質分岐1」です。統合を始める場合は統合プロジェクトが新しい主になり、構成元の部門・業種・生成プロジェクトは読取専用の参照元へ切り替えます。品質分岐を終えたらHANDOFFを主へ戻し、分岐側を非アクティブにします。コース一覧を先に全部作りません。

#### 次のチャレンジを始める前に、すでに作った物を探す

1. `CURRENT_MANIFEST`と、現在の`CASE_ID`にある`OUTPUT_INDEX.md`を見て、同じ完成品があるか確認する。
2. あれば本問の完成条件と比較し、**移行認定（合格相当） / 差分改善 / 新規制作**から一つを選ぶ。
3. 移行認定では、実際にファイルを開き、出典、版、権利、未接続、テスト範囲を人が確認する。
4. 差分改善では、足りない条件だけを作り、合格版を別物として複製しない。
5. 新規制作は、同等成果物がない時だけ選ぶ。

移行認定は課題の省略ではなく、本問の**全完成条件を満たす既存成果物**を実際に開き、能力を証拠付きで合格相当と認める仕組みです。入力素材として使えるだけなら差分改善を選びます。PROGRESSの状態は「未着手 / 作業中 / 確認待ち / 移行認定（合格相当） / 合格 / 保留」から選びます。

#### 途中で生成特化へ分岐して戻る

部署別・業種別の標準分岐点は03または06です。ただし、[全体地図のコード単位クロスウォーク](./TEXTBOOK_CURRICULUM_MASTER_MAP.md#高重複コースのコード単位クロスウォーク)に個別の出発コードがある場合はそちらを優先し、媒体品質だけが不足している時に生成特化へ分岐できます。

~~~text
主コースの標準03・06または個別指定コード
        │
        ├─ CROSS_TRACK_HANDOFFを作る
        ▼
生成特化で移行認定または差分改善
        │
        ├─ 採用版・権利・公開状態を返す
        ▼
元の主コースの次の未完了コードを再開
~~~

例: `MKT-03 → ADS → MKT-04〜10`、`SLS-05 → SLD-01〜03またはWEB → SLS-06〜10`、`REV-03 → XLS-03 → REV-04〜10`、`REV-07 → XLS-04 → REV-08〜10`、`FIN-03 → XLS-05 → FIN-04〜10`、`SAL-03 → BRDまたはWEB → SAL-04〜10`、`CRT-03 → 必要な生成コース → CRT-04〜10`。売上請求書、買掛の支払確認、管理用損益候補、入出金予定を同じ流れにせず、元の会社、顧客、料金、商品、承認済み計算を生成側で作り直しません。問を飛ばせるのは、飛ばす各コードに移行認定（合格相当）の証拠を残した場合だけです。

#### CASE_COREを全コースで共有する

親フォルダの`00_START/CASE_CORE/`に`CASE_INDEX.md`を置き、練習事業ごとに`CASE-001/`、`CASE-002/`のような独立フォルダを作ります。現在使う`CASE_ID`はROUTE_CARDで一つだけ指定します。

| ファイル | 内容 |
|---|---|
| `CASE_INDEX.md` | CASE_ID、テーマ、開始日、現在の利用状態、正本フォルダ |
| `FACTS.md` | 会社、商品・サービス、料金、場所、人物、確認済み事実、確認日 |
| `CASE_IDS.md` | 顧客、商品、案件、注文等の共通IDと意味 |
| `BRAND_CORE.md` | 採用色、文字、ロゴ・画像の状態、禁止表現 |
| `APPROVALS.md` | 誰が何を判断・公開・送信・支払できるか |
| `SOURCE_INDEX.md` | 正式資料、出典、版、更新条件 |
| `OUTPUT_INDEX.md` | `CASE_ID / 成果物種別 / 正本プロジェクト / 課題コード / 版 / 場所 / 権利 / 公開状態`で、既存成果物を探す索引 |

D・I・Gごとに別の架空会社を作らず、同じ`CASE_ID`を使います。別テーマへ変える場合は、新しいCASEフォルダを作り、`CASE_INDEX.md`とDECISIONSへ変更理由と開始日を残します。以前のCASEは上書きしません。

#### CROSS_TRACK_HANDOFFで渡すもの

通常の章引継ぎとは別に、教材をまたぐ時は次を`CROSS_TRACK_HANDOFF.md`へ記録します。

- 出発コード、到着コード、元へ戻るコード
- 分岐理由と終了条件
- `CASE_ID`と共通の事実・出典
- 渡す合格版、版番号、完成条件
- 再制作しない成果物
- 権利、同意、AI生成表示、公開状態
- データ項目、役割、禁止操作、未接続
- 生成側または専門側で追加する差分
- 元コースへ返す採用版と残りの作業

`CROSS_TRACK_HANDOFF.md`の正本は**出発側主プロジェクトの`05_HANDOFF/`**に置きます。到着側は、出発側の正本パスと版を明記した参照または版付きコピーだけを持ちます。分岐から戻る時は、採用版と差分を出発側の正本へ追記して版を更新します。

### 部署別200は「1部門＝1専門プロジェクト」

[主要20部門×10チャレンジ](./TEXTBOOK_DEPARTMENT_TRACKS_200_DRAFT.md)は、20部門全部を一つの巨大なプロジェクトへ入れません。受講者が選んだ1部門につき1つの専門プロジェクトを作り、その中で準備・試作、制作、確認・完成のチャットを分けます。完成品と短い引き継ぎメモで続きを渡し、その部門の10問で一つの代表作品を育てます。選んだ1部門だけでも修了できます。

| 学び方 | プロジェクト | チャット | 成果物 |
|---|---|---|---|
| 1部門を選ぶ | 例: D03_SALES | D03_01-03_準備試作 / 04-06_制作 / 07-10_確認完成 | 営業10問を統合した代表作品 |
| 隣接部門も学ぶ | 例: D04_REVOPSを別に作る | D04専用の工程別チャット | 営業企画・業務改善の代表作品 |
| 部署横断の全体卒業制作へ進む | 例: X01_CROSS_DEPARTMENT | 関係部門のHANDOFFを受け取る新チャット | 複数部門をつなぐ統合作品 |

- 隣接部門を学ぶ時も、既存の専門プロジェクトへ10問を追加せず、別の専門プロジェクトを作る。
- 各専門プロジェクトには、共通編と同じ「00_BRIEF〜05_HANDOFF」の6フォルダを置く。
- 他部門へ再利用するものは、相手が必要な完成品、データ項目、決定、制約だけをHANDOFFへ書き出す。チャット全文や不要な部門資料は渡さない。
- 複数部門を同時に扱う新しい統合プロジェクトは、部署横断の全体卒業制作を始める時だけ作る。統合側を現在の主プロジェクトにし、各部門の代表作品は読取専用の正本として残す。
- 同じプロジェクト内でも、成果物または工程が変わる所でチャットを分ける。次のチャットへは採用した完成品、決定、未確認事項だけを短い引き継ぎメモと一緒に渡す。

部署別フォルダは、選んだ時だけ親練習フォルダへ追加します。

~~~text
AIJUKU_受講者名/
├─ D03_SALES/
│  ├─ 00_BRIEF/
│  ├─ 01_INPUT/
│  ├─ 02_WORKING/
│  ├─ 03_OUTPUT/
│  ├─ 04_TEST/
│  └─ 05_HANDOFF/
├─ D04_REVOPS/                 # 学ぶ場合だけ別プロジェクトで追加
└─ X01_CROSS_DEPARTMENT/       # 部署横断の全体卒業制作の時だけ追加
~~~

#### 部署別へ進む入口

#### プレゼンとExcelは、実ファイルを開いて初めて「できた」にする

SLDでは、`SLD-03`で白黒5枚の編集可能な初回`.pptx`を作り、同じファイルを`SLD-04〜06`でデザイン、図表、15枚＋補足5枚へ育てます。`SLD-08`で3分版・10分版とPDFを作り分け、`SLD-09〜10`で全スライドを表示して修正後の`.pptx`とPDFを再確認します。聞き手は役員に限定せず、お客様、仲間、社内会議、提案先、説明会参加者等から選びます。文章案、画像、Markdown、PDFだけではPowerPoint完成にしません。

XLSでは、売上20件の見える化から入力規則付き台帳と見積書へ進み、`XLS-04`では売掛側の売上請求書下書き、`XLS-05`では買掛側の経費・支払確認候補を作ります。`XLS-06`は正式な損益計算書ではない管理用損益候補であり、入金予定・支払予定は別表にします。`XLS-09`では過去月を差し替えず、新しい行・月を追記する担当者、確認者、更新日を残します。`XLS-10`で会社用Excelパックへまとめますが、コースで得るのは**テンプレート利用承認**までです。個別の見積・請求等は「教材用 / 発行前下書き / 個別承認済み / 正式発行済み（REV/FINの記録先）」を別管理します。

Web表、CSV、計算結果の文章だけではExcel完成にしません。`.xlsx`をExcelまたは対応アプリで開き、全シート、数式エラー、再計算、入力規則、フィルター、表示、印刷範囲を確認し、主要な金額を元データと別計算例で照合します。税、価格、会計処理、顧客情報、個別承認、正式発行、配布範囲は担当者が確認し、マクロ、外部接続、送信は会社承認なしに有効化しません。

XLSからSLDへ値・表・グラフを渡す標準方法は、検証済みXLSからの静的書出しです。PowerPointへ元ブック名、シート名、セル範囲、基準日、版を注記し、元ブックの埋込みと外部リンクは標準禁止にします。会社が例外承認した場合だけCURRENT_MANIFESTへ依存関係を記録し、別フォルダとオフラインでリンク切れを試します。配布前にはリンクを解除した静的版を作り、リンク用キャッシュや元データが残っていないか確認します。

SLDとXLSの合格証拠には、実ファイル、検証したアプリと版、全ページまたは全シートの確認記録、修正後に再度開いた記録を残します。さらに、ノート、コメント、非表示スライド・シート、文書プロパティ、埋込ファイル、定義名、外部接続・キャッシュを検査します。教材・AIペルソナによる模擬レビューと、同意済みの実人テストは別実績です。レビュー区分、実人数、評価方法、発見事項、未検証事項を記録し、模擬レビューだけを「実人テスト済み」としません。

APPのPWA・プレビュー開始パックは`APP-01〜05`まで使えます。`APP-06〜10`へ進む場合は、先にネイティブ対応スターターへ移行し、対応するMac・XcodeまたはAndroid開発環境を用意します。移行しない場合はPWA・プレビューの到達状態で終了し、本人実機導入済みまたはAPPコース総合とは記録しません。

### 推奨するチャットの切り方

同じ成果物を育てる間は一つのプロジェクトに置きますが、10課題を一つの長い会話へ詰め込みません。基本は01〜03の準備・試作、04〜06の制作、07〜10の確認・完成でチャットを分けます。作品の区切りが異なる場合は成果物ごとに分け、採用した完成品と短い引き継ぎメモで次へ渡します。別コースへ移る時は新しいプロジェクトを作ります。

| 方式 | 良い点 | 起きやすい問題 | 向いている場面 |
|---|---|---|---|
| 全部を1チャット | 前の会話が残り、開始が簡単 | 長くなるほど条件が混ざり、古い案を採用しやすい。問題箇所を探しにくい | 短い体験版や1章だけの受講 |

| 推奨ハイブリッド | 同じプロジェクトで作品を引き継ぎ、工程ごとに文脈を整理できる | チャットを替える時に短い引き継ぎメモが必要 | 作品を長く育てる通常受講 |

### 白紙から始めない開始キット

受講開始時に、講師側から次の一式を複製して渡します。受講者はフォルダ構造や表を一から作らず、中身を自分用に交換するところから始めます。最初に複製するのは00_STARTと、選んだ1作品分だけです。未選択のプロジェクトは追加しません。

- 選んだ作品の空フォルダと、本書の記録テンプレートを配置したひな型
- START_HERE、主教材・品質分岐・戻り先を記録するROUTE_CARD、Lv.01–200入りMASTER_PROGRESS
- 全トラックで同じ会社・商品・顧客・共通IDを使うCASE_CORE、既存成果物を探すOUTPUT_INDEX、教材間を移るCROSS_TRACK_HANDOFF
- 架空会社のプロフィール、規程、商品、問い合わせ、会議メモ、取引、利用者、権限の教材データ
- プロフィール画像、仮ロゴ、配色、サンプル写真、ダミー文書などのCOMMON_ASSETS
- 各章の最初に貼れるPROMPT_STARTERSと、完成見本へのリンク
- 正常、入力漏れ、重複、権限外、接続失敗を含む共通テストデータ
- 藤本への相談先、送信方法、受付時間、返信目安、緊急時の扱いを講師が記入したCONTACT_FUJIMOTO
- 実データを入れる前に確認するSAFETY_CHECK

実務データの利用許可がない人や外部サービスのアカウントがない人も、教材データで同じ学習ループを完了できます。教材版から実務版へ移る時は、別の作業コピーを作り、権限、個人情報、公開、課金を再確認します。

### 一つのチャレンジで繰り返す7ステップ

1. **今日の完成イメージを見る:** タイトルを読み、「誰が・いつ・何に使うか」を一言で想像する。
2. **続きから開く:** PROJECT_BRIEF、現在のPROGRESS、今回の入力、直前の合格版を開く。
3. **AIへ依頼する:** PROMPT_STARTERSを土台に、変更点、変えない点、完成条件を伝える。
4. **実際に触る:** 文章を読む、ボタンを押す、数字を入れる、画像を開くなど、利用者と同じ操作をする。
5. **直す:** 期待と実際の差をAIへ渡し、一度に一つか少数の変更を依頼する。
6. **証拠を保存する:** 通常レベルは合格版または変更差分を保存する。指定チェックポイントと高リスク操作では画面、出力、テスト結果も保存する。
7. **進捗を更新する:** PROGRESS、必要ならDECISIONSとCOST_LOGを更新し、次にする一手を書く。

各教材ページでは、タイトルの直後に「こんな時に欲しくなる」「やってみること」「できあがるもの」「仕事でこう使える」「ここだけは人が決める」を短く並べます。読み始める前から専門用語を覚えさせず、まず完成見本か完成イメージを見せ、作りながら必要な言葉だけ覚える順番にします。

AIの返答を受け取っただけでは完了にしません。「開けた」「押せた」「期待した結果になった」「戻せた」など、チャレンジに合う証拠を一つ以上残します。ただし、通常レベルで必須なのは「合格版または変更差分」とPROGRESSの1行だけです。詳細な画面証拠は章内03・08・09・10、および外部送信、公開、課金、権限変更などの高リスク操作で残します。

通常レベルの修了条件は、完成品を開いて一度使う、合格版または変更差分を保存する、PROGRESSの1行と必要な人の確認を残す、の3点です。正常例と失敗・例外の詳しい試験は章内03・08・09・10と、高リスク操作で行います。Lv.01–20は1回10〜30分で小さな達成を得る設計とし、Lv.21以降は1回45〜90分を上限の目安に区切ります。時間は合否条件ではなく、終わらなければ「保留」と次の一手を残せば続きから再開できます。

教材・AIペルソナの評価は、協力者がいない時の改善材料にはできますが、実際の人へ見せた実績ではありません。04_TESTには「模擬レビュー / 実人テスト」の区分、実人の参加人数、対象者の役割、評価方式、実施日、分かったこと、未検証事項を残します。実人0名なら、人数欄へ0と書きます。

| 章内の位置 | 役割 | 保存するチェックポイント |
|---|---|---|
| 01–03 | 完成見本を開き、入力と土台を自分用に変え、中心機能を一度動かす | 基本動作版 |

#### 一つ前の完成品を次の入力にする例

Lv.15とLv.16は別課題に見えても、作り直しません。Lv.15で作った一枚画像の設計図3案から1案を選び、Lv.16で実画像にし、Lv.17で雰囲気違いを比較し、Lv.18でスマートフォン表示を直し、Lv.19で権利と事実を確認し、Lv.20で発信スターターキットへ収めます。各レベルは、直前の合格版へ一つの能力または確認を足す関係です。

### 新しいチャットを作る条件

#### 新しく作る

- Lv.10、20、30……の章末を合格し、次の章へ進む時
- 会話が長くなり、AIが古い案と合格版を混同し始めた時
- 本、プレゼン、Excel等の制作と、独立した品質確認・安全確認を分けたい時
- 別案を比較したいが、現在の合格版を崩したくない時
- 参加者、公開範囲、機密区分が変わり、文脈を分離する必要がある時

章の途中で新しくする場合は、先に暫定HANDOFFを作り、チャット名へ「B」などの枝番号を付けます。例: 「P04_C09B_Lv86-90_受付サイト修正」。

#### 作らず同じチャットを続ける

- 同じ章、同じ完成品、同じ入力を使うLv.01–09の通常制作
- 誤字、色、配置、一つの計算式など、現在の出力を直す時
- エラー画面を示し、直前の操作を一緒に再現する時
- AIの提案へ質問し、採用するか決める途中

「うまくいかないから毎回新規チャット」は、同じ説明と試行を繰り返しやすくなります。まず現在のチャットで期待、実際、エラー、変えない点を整理します。

### 費用と待ち時間を減らすルール

- 変更していない資料は毎回再アップロードしない。ChatGPTのプロジェクト参照資料に同じ版があり、実際に読めることを確認できた場合はその名前と版を指定し、参照できない場合だけ今回必要な最小ファイルを添付する。正本は手元または承認済み共有場所に保つ。
- 同じ事実を章ごとに再調査せず、出典、確認日、利用箇所を「SOURCES.md」へ残して再利用する。更新が必要な事実だけ調べ直す。
- 画像は最初から大量生成せず、1〜2案のラフで方向を決めてから必要なサイズを作る。
- ロゴ、色、文章、利用者名、テスト用の会社情報はCOMMON_ASSETSとSAMPLE_DATAから使う。
- 正常例だけでなく、入力漏れ、重複、権限外、接続失敗の共通テストデータをP04とP05で再利用する。
- AIへ「全部作り直して」ではなく、変更箇所、残す箇所、合格条件を指定する。
- 各章末で会話の要約をHANDOFFへ移し、次のチャットへ会話全文を貼らない。
- COST_LOGとHANDOFFは章末にAIへ下書きさせ、受講者が事実を確認する。有料処理や想定外の再生成が発生した時は、その時点でも更新する。
- 新たな課金が発生する画像生成、外部接続、公開、有料プラン開始の前に、サービス名、課金単位、固定費、従量費、最大実行回数、想定最大額、支払者、停止・解約方法を確認する。費用上限が空欄または金額不明なら有料操作をせず、教材モックへ切り替える。

### 困った時の3段階

#### 1｜同じチャットでAIへ修正を依頼する

期待した結果、実際の結果、直前の操作、エラー全文または画面、変えてよい部分、変えない部分を一緒に渡します。一度に多く直さず、原因確認と最小修正を依頼します。

#### 2｜別の確認チャットで原因を切り分ける

合格版、問題を再現する最小データ、エラー、試したことだけを渡し、「まだ変更せず、原因候補と確認順を出して」と依頼します。確認結果は元の制作チャットへ戻し、採用した修正をDECISIONSへ残します。

#### 3｜藤本へ相談する

藤本への相談はいつでもできます。「3回修正または20分」は、相談してよい条件ではなく、必ず自力作業を止めて相談へ切り替える上限です。次の操作や質問内容そのものが分からない場合は、その時点で相談します。権限、公開、課金、個人情報、安全に関わる場合も、3回または20分を待たず操作を止めます。相談先、送信方法、受付時間、返信目安、緊急時の扱いは、講師がCONTACT_FUJIMOTOへ記入します。

- 同じ問題へ3回修正を試しても直らない
- 20分以上、次の確認方法が分からず停滞した
- 権限変更、外部公開、課金、契約、個人情報、機密、安全に関わる
- 教材、講師の指示、会社の規則、完成条件が矛盾して見える
- 既存データの削除、上書き、送信、公開など、元へ戻しにくい操作が必要

#### 藤本への相談テンプレート

~~~markdown
# 制作相談

- レベル:
- 目標:
- 現在の状態:
- 期待した結果:
- 実際の結果:
- 試したこと1:
- 試したこと2:
- 試したこと3:
- エラー全文:
- 画像・ファイル・証拠の場所:
- 最後に動いた版:
- 権限・公開・課金・個人情報への影響:
- 希望する助け: ヒント / 次のプロンプト / 一緒に修正
~~~

個人情報、パスワード、APIキー、契約上共有できない資料は相談文へ貼りません。必要な場合は、伏せ字や教材データで再現します。

藤本から回答を受けたら、採用した助言と理由をDECISIONS、再開するレベルと最初の一手をPROGRESSへ残します。相談したこと自体は不合格や減点にしません。

### チェックポイントとバージョン運用

ファイル名は「プロジェクト_章_レベル_版_短い名前」で揃えます。例: 「P04_C08_Lv78_v02_company-site」。日付だけで管理せず、どのレベルの何版かを残します。

| 時点 | 推奨版 | 意味 |
|---|---|---|
| 章内03 | v0.3 | 中心機能が一度動いた基本動作版 |
| 章内08 | v0.8 | 必要機能を加えた機能完成版 |
| 章内09 | v0.9 | テストと安全確認へ回す合格候補 |
| 章内10 | v1.0 | 章末作品またはコース総合として統合し、HANDOFFを付けた版。共通Lv.200と複数コース統合は全体卒業制作 |

- 作業中は02_WORKINGへ保存し、合格した版だけを03_OUTPUTへ複製する。
- 最後に合格した版を上書きせず、新しい版で修正する。
- 04_TESTには、どの版を何で試し、何が合格・不合格だったかを残す。
- Web作品は動くファイル一式または書出しZIP、使用データは個人情報を除いた書出し、重要判断はDECISIONSをチェックポイントへ含める。
- PowerPoint作品は編集可能な`.pptx`を実アプリで全スライド表示し、文字切れ、重なり、画像、書体、図表を直した後、再度開いた記録と配布用PDFをチェックポイントへ含める。
- Excel作品は`.xlsx`を実アプリで開いて再計算し、全シート、数式エラー、入力規則、主要値、表示、印刷範囲を直した後、再度開いた記録をチェックポイントへ含める。`XLS-09`以降は過去データを上書きせず、新規行・月の追記担当、確認者、更新日も試す。
- Office作品はノート、コメント、非表示スライド・シート、文書プロパティ、埋込ファイル、定義名、外部接続・キャッシュを配布前に検査し、除去後のファイルをもう一度開く。
- XLSからSLDへは検証済みの値・表・グラフを静的書出しし、元ブック、シート、範囲、基準日、版を注記する。元ブック埋込・外部リンクは標準禁止とし、会社承認時だけ依存関係、別フォルダ・オフライン試験、配布前解除を記録する。
- 教材・AIペルソナによる模擬レビューと実人テストは別の証拠にし、実人数、役割、評価方式、未検証事項を記録する。
- Excelはテンプレート利用承認と個別帳票の発行状態を分け、正式発行済みとする時はREVまたはFINの記録先を残す。
- 外部接続の認証情報、APIキー、証明書の秘密鍵、`.p12`、Android keystore、署名用パスワードはAI入力、Git、成果物、ZIPへ入れない。
- 新版が失敗したら、最後の合格版へ戻してから原因を一つずつ確認する。
- 使わなくなった版はすぐ削除せず99_ARCHIVEへ移し、復旧できる期間を決める。

### 章をまたぐ引き継ぎ手順

1. Lv.10、20、30……の完成チェックを終える。
2. 合格版を03_OUTPUT、証拠を04_TESTへ保存する。
3. PROGRESS、DECISIONS、COST_LOGを更新する。
4. HANDOFFへ「完了」「未完了」「変えない条件」「次の一手」を書く。
5. CURRENT_MANIFESTを更新し、現在の合格版本体へ実際にアクセスできることを確認する。
6. 次章の新しいチャットを作り、引き継ぎ4点セットを渡す。
7. AIに内容を要約させ、「事実」「決定」「未確認」を分けて確認する。
8. 前章の中心機能がまだ動くことを一度確認してから、新機能を足す。

### 高度編へ進む時の最初の15分

1. 4冊の章見出しとタイトルだけを5分眺め、「完成したら一番うれしいもの」を一つ選ぶ。
2. そのタイトルを声に出し、「誰に・いつ見せたいか」を一言で書く。難しそうなら同じコースの01〜03か開始見本を選ぶ。
3. 選んだ教材のらくらく、標準、実務挑戦またはクリエイター実践のどこまで進むかROUTE_CARDへ記録する。
4. 00_STARTと、今回選んだ1プロジェクトの開始キットだけを親練習フォルダへ複製する。
5. PROJECT_BRIEFへ「作りたいもの」「できたらうれしいこと」「仕事で最初に試す場面」を書く。
6. 最初の工程のチャットを開き、AIへ「完成見本を先に見せて。次に、最初の一手だけ一緒に進めて」と依頼する。
7. 触れる最初の完成物を保存し、PROGRESSの状態を「作業中」に変える。詰まったら、その場で藤本へ相談してよい。

200レベルを一直線に完走することだけが目的ではありません。自分が使いたい一作品を完成させる、P04だけを育てる、共通編の途中から部署別・業種別・生成特化作品へ進むなど、選んだ経路と完成品が説明できれば、その学び方も正式なルートとして扱います。
