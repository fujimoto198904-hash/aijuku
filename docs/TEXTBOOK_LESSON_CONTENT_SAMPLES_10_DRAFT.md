# 藤本実学塾 ChatGPT実践教科書 本文サンプル10

> 状態: 品質見本 / Web表示と同じ正本から自動生成
> 更新日: 2026年9月2日
> 目的: 「これなら自分にもできそう」と思える本文になっているかを、10種類の完成品で確かめる

この10本は、全730課題の品質見本です。説明を覚える教科書ではありません。練習用の雑なメモや資料を、その仕事で一番楽な方法でChatGPTに渡し、まず何かを完成させます。

このファイルの課題本文は、`lib/textbook-lessons/`の章別正本から生成します。Webと原稿を別々に直して内容がずれないようにするため、本文を変える時は正本を直してから`npm run build:lessons`を実行します。

## いちばん最初に、これだけ準備します

### 1｜開いた課題の資料だけ取得する

課題に必要な架空の練習データは、各教科書ページの「この課題で使うファイル」に並びます。自分で業種を選んだり、大きなZIPを展開したりする必要はありません。TXTはその場でコピーでき、PDF・Word・Excelなどは必要なファイルだけ1件ずつ取得できます。

### 2｜練習場所は一つ、会話は作る物ごとに分ける

各課題ページを練習の入り口にします。ChatGPTのプロジェクトを使える場合も、練習用を一つ作れば十分です。ただし10課題を一つの長い会話へ詰め込まず、準備・試作、制作、確認・完成など、作る物や工程が変わる所で新しいChatを開きます。次のChatへは、完成品と短い引き継ぎメモだけを渡します。

### 3｜素材は、仕事に合う方法で渡す

- 短いメモは、開いて中身をコピーし、入力欄へ貼る
- PDF、Word、Excelは、見た目や表も必要な時だけ添付する
- 一回の文章づくりは`Chat`、実ファイルを作って何度も直す時は`Work`を使う
- `Work`が表示されない時は、`Chat`へ同じように貼る・添付し、できた物を自分で保存する

各課題の`課題/01メール.txt`のような表記は、素材を探すための場所案内です。ファイル名やパスをAIへ正確に言えるかは、課題の合否に関係ありません。

### 4｜できあがった物を「完成」へ残す

普通のChatやファイル添付で進めた場合は、できあがった文章をコピーするか、生成されたファイルをダウンロードし、デモデータの`完成`フォルダへ入れます。`Work`で進めた場合は、AIに保存を頼めます。

どの方法でも、**作る → 実際に触る → 気になる所を一つ直す → 保存した物を開く**の順で進めます。メール送信、予定登録、公開、支払い、契約は勝手に進めさせません。

最後のステップアップは任意です。今の完成品へ便利を一つ足す練習で、表示された別課題を正式に修了したことにはなりません。

## サンプル1｜Lv.05 走り書きのメモを、送信前のメールにしてみよう

### 今日はこれを作る

**目安:** 最初の完成まで 5〜10分

**今回手元に残る物:** 件名、お願い、期限または「未定」が分かる、送信前のメール下書き

### 使うもの

展開したデモフォルダから、次の材料を使います。

- `課題/01メール.txt`

> **共通操作メモ:** TXTはコピー。Chatの入力欄を使います。

### まずこう言ってみる

材料を渡したすぐ下に、普段の言い方のまま送ります。

```text
これ、相手に返すメールにして。ちょっと急ぎ。あんまり堅くしないで。まだ送らないで。
```

### 出てきた物を実際に触る

AIが「できました」と言っただけでは完成にしません。次を自分で一度触ります。

- 件名だけで用件が分かるか読む
- 相手に確認してほしいことを指で追う
- 未定の話が決定事項になっていないか元メモと比べる

### 出力を上げるコツ

全部を言う必要はありません。気になるものを一つだけ選びます。

**少し固い**

```text
いつもの取引先に送る感じにして
```

**期限が見えない**

```text
期限が件名を見ただけでも分かるようにして
```

**余計な話がある**

```text
元のメモと比べて、勝手に足した所だけ教えて
```

### やりがちなミス

- 元のメモにない名前、電話番号、約束が増えている
- 「確認後に進める」が「進めてください」に変わっている
- 期限が本文に埋もれている
- 宛先や添付ファイルを見ないまま送ろうとしている

### ここまでできたら完成

- 元のメモにない約束が増えていない
- 件名、お願い、期限または「未定」が読める
- 保存したメール下書きをファイル管理画面から開けた

普通のChatで進めた場合は、文章をコピーするか、できたファイルをダウンロードして`完成`フォルダへ入れます。`Work`でデモフォルダを開いて進めた場合は、次の一言で保存を頼めます。

```text
この下書きと、うまくいった一言と、まだ確認が必要な所を、完成フォルダに「メール.md」で保存して。送信はしないで。
```

保存した物をもう一度開けたら、今回の課題は完成です。

### 自分の仕事なら

明日送りそうな依頼、催促、日程調整、お詫び、社内連絡の一つへ置き換えます。最初は実名を使わず「A社」「担当者さん」で試します。

### 困ったら藤本に聞く

止まった画面のスクショと、「Lv.05で、ここまでできた：＿＿。ここで止まった：＿＿」を藤本へ見せます。うまく説明できなくても大丈夫です。実在する個人情報や秘密は隠します。

### ステップアップ｜Lv.06 このメールを、催促やお詫びにも使える形にしよう

これは今の完成品へ便利を一つ足す任意の発展です。Lv.06を正式に終えた扱いにはなりません。下の一言を今いるChatまたはWorkの続きで試すか、詳しい手順を開いて次の課題として進めます。

**今回できた物を、そのまま使う:** 今作った「メール.md」をひな形にして、元の内容と未確認事項をそのまま引き継ぎます。

**次に増えること:** 同じ内容を、言いにくい二つの場面に合わせて書き分けられます。

**次の正式課題:** Lv.06

```text
今のメールを元に、返事がない時の催促用と、こっちが遅れた時のお詫び用も作って。どっちも堅すぎない感じで。まだ送らないで。
```

## サンプル2｜Lv.24 「自分に何が関係ある？」まで分かる自分新聞を作ろう

### 今日はこれを作る

**目安:** 最初の完成まで 10〜15分

**今回手元に残る物:** 日付、元記事へのリンク、自分との関係、今日の一歩が付いた「自分新聞 第1号」


### 出てきた物を実際に触る

AIが「できました」と言っただけでは完成にしません。次を自分で一度触ります。

- 記事を一つ選び、リンクを実際に開く
- 元記事の日付と新聞の日付を比べる
- 自分の仕事との関係が一言で分かるか読む

### 出力を上げるコツ

全部を言う必要はありません。気になるものを一つだけ選びます。

**朝から長い**

```text
3分で読める量にして
```

**自分に関係ない**

```text

```

**確かめられない**

```text
見出しごとに元記事の日付とリンクを付けて
```

### やりがちなミス

- リンクを押しても元の記事へ行けない
- 古い記事を今日のニュースとして扱っている
- 記事にない数字や結論が足されている
- 自分に関係のない話ばかりで読む気にならない

### ここまでできたら完成

- 今日の日付と、実際に開けた記事が3本前後ある
- 各記事に「自分にどう関係するか」が一言ある
- 保存した新聞をもう一度開けた

普通のChatで進めた場合は、文章をコピーするか、できたファイルをダウンロードして`完成`フォルダへ入れます。`Work`でデモフォルダを開いて進めた場合は、次の一言で保存を頼めます。

```text
この新聞と、使った記事のリンクと、まだ確かめられていない所を、完成フォルダに「新聞.md」で保存して。
```

保存した物をもう一度開けたら、今回の課題は完成です。

### 自分の仕事なら

まず「業界」「地域」「競合」「制度変更」の一つだけに絞ります。

### 困ったら藤本に聞く

止まった画面のスクショと、「Lv.24で、ここまでできた：＿＿。ここで止まった：＿＿」を藤本へ見せます。うまく説明できなくても大丈夫です。実在する個人情報や秘密は隠します。

### ステップアップ｜Lv.28 この第1号を、毎朝読める自分新聞に育てよう

これは今の完成品へ便利を一つ足す任意の発展です。Lv.28を正式に終えた扱いにはなりません。下の一言を今いるChatまたはWorkの続きで試すか、詳しい手順を開いて次の課題として進めます。

**今回できた物を、そのまま使う:** 今作った「新聞.md」と、もっと読みたい記事・いらない記事の好みを使います。

**次に増えること:** 好みを残し、同じ新聞を朝に繰り返し作れるようにします。

**次の正式課題:** Lv.25

```text
この新聞いい感じ。もっと読みたい話と、いらない話を一個ずつ聞いて。その好みで、朝起きたら読める形にしたい。まず次も同じように作れる一言にして。自動でできるなら、設定前に条件を教えて。
```

### 使うもの

展開したデモフォルダから、次の材料を使います。

- `課題/03画像.txt`

**前の課題から引き継ぐ物:** IMG-02で採用した世界観と一番良かった試作を参照画像にします。

- できた四枚を順に開く

全部を言う必要はありません。気になるものを一つだけ選びます。

```text

```

**高級すぎる**

```text

```


- 会社名やロゴが勝手に変わっている
- 画像ごとに色や雰囲気がばらばらになっている

### ここまでできたら完成

- 画像の説明文ではなく四枚の画像ファイルを実際に開けた
- 文字、会社名、人物や物に大きな崩れがなかった
- 四枚、使った一言、何をどう直したかの履歴を用途が分かる名前で保存できた

普通のChatで進めた場合は、文章をコピーするか、できたファイルをダウンロードして`完成`フォルダへ入れます。`Work`でデモフォルダを開いて進めた場合は、次の一言で保存を頼めます。

```text
この四枚、使った一言、何をどう直したか、まだ気になる所を「03_シリーズの顔と4用途版」に保存して。用途が分かるファイル名にして。
```

保存した物をもう一度開けたら、今回の課題は完成です。

## サンプル10｜Lv.180 止める・待つ・戻す・人のOKで再開する「AI緊急運転室」を作ろう

### 今日はこれを作る

**目安:** 三ケースの停止から再開まで 70〜100分

**今回手元に残る物:** 緊急停止、新規停止、処理中の確認待ち、直前の合格版へのバックアップ復元、権限者の再開承認、四項目の時系列ログが一画面にそろう未公開のAI緊急運転室

### 使うもの

展開したデモフォルダから、次の材料を使います。

- `課題/14AIルール.docx`
- `30_PDF/05_帳票/帳票_09_公開前チェック.pdf`
- `30_PDF/05_帳票/帳票_10_AI利用記録.pdf`

**前の課題から引き継ぐ物:** Lv.171〜179のテストランナー、品質数字、拒否・防止結果、追跡ログ、監視警告、停止画面、確認待ち一覧、手作業CSV、直前の合格版を同じWorkで開きます。

> **共通操作メモ:** 前の完成物を使う ／ 資料はこのページから取得。Workが表示されるならそこで続けます。なければChatへ同じ内容を送って進めます。

### まずこう言ってみる

材料を渡したすぐ下に、普段の言い方のまま送ります。

```text
緊急運転室を仕上げたい。「資料にないことを言った」「古い資料を使った」「個人情報を入れそうになった」を架空データで一件ずつ起こして、毎回、新規を停止、動いてる処理を確認待ち、直前の合格版へ復元、権限のある人が再開OK、の順で実際に押す。順番を飛ばせないようにして、まだ公開しないで。
```

### 出てきた物を実際に触る

AIが「できました」と言っただけでは完成にしません。次を自分で一度触ります。

- 「資料にないことを言った」を発生させ、新規停止→処理中を確認待ち→直前の合格版へ復元→権限者の人が再開承認の順で実際に押す
- 「古い資料を使った」を発生させ、新規停止→処理中を確認待ち→直前の合格版へ復元→権限者の人が再開承認の順で実際に押す
- 「個人情報を入れそうになった」を発生させ、新規停止→処理中を確認待ち→直前の合格版へ復元→権限者の人が再開承認の順で実際に押す
- 各ケースの再開前に別の役で再開を押し、拒否されて停止が続くか確かめる
- 三ケースの時系列ログを開き、全操作に時刻・操作者・理由・対象があるか照合する

**最初の異常ケースを検知したら**

```text
まず「新規処理を停止」を押す。停止表示を見てから新規案件を一件試し、拒否を確認する。次に、動いている処理を全部「確認待ち」へ移し、進行中がゼロになるまで一覧を開く。まだ復元も再開もしないで。
```

そのあと、実際に次を確かめます。

- 停止ボタンを自分で押し、新規の拒否と全処理中案件の確認待ちを順に確認する

**処理中がすべて確認待ちになったら**

```text
その次にだけ、バックアップ一覧から「直前の合格版」を選んで復元する。データ、設定、プロンプトまたはアプリの前後を比べ、同じ点検を再実行して合格を確認する。停止状態は保って。
```

そのあと、実際に次を確かめます。

- 復元対象の合格記録を読み、復元前後と再点検結果を自分で見比べる

**直前の合格版への復元と再点検が終わったら**

```text
最後にだけ、権限のある人の再開確認画面を出す。止めた理由、対象、確認待ち件数、復元した版、再点検結果をその人が見て承認した時だけ再開して。承認前や別の役では動かさないで。
```

そのあと、実際に次を確かめます。

- 権限者の役へ切り替え、復旧内容を確認してから再開承認を自分で押す

**一ケースが再開まで通ったら**

```text
同じ四段階を残りの異常ケースでも最初から繰り返す。各操作に時刻、操作者、理由、対象を必ず残し、三ケースのログを混ぜず時系列で並べて。
```

そのあと、実際に次を確かめます。

- 三ケースそれぞれの停止、確認待ち、復元、再開承認の四操作をログで指差し確認する

### 出力を上げるコツ

全部を言う必要はありません。気になるものを一つだけ選びます。

**今どの段階か迷う**

```text
停止、確認待ち、復元、再開承認の四段階を上に固定し、完了した所だけ印を付けて
```

**確認待ちを見落とす**

```text
処理中が一件でも残る間は復元へ進めず、対象一覧を先に開いて
```

**再開判断を渡したい**

```text
権限者向けに停止理由、対象、復元版、再点検結果だけを一枚へまとめて
```

### やりがちなミス

- 異常を検知しても新規処理だけ止めず、次の案件が動き始める
- 処理中案件が残ったまま復元へ進み、途中の外部処理が完了してしまう
- 直前の版というだけで不合格版を選び、合格記録を確かめず復元する
- 復元が終わった表示だけで、権限者の再開承認を飛ばして自動再開する
- 三ケースのどれかを説明だけで済ませ、四段階を実際に押していない

### ここまでできたら完成

- 三つの必須異常ケースすべてで、新規処理を実際に停止できた
- 各ケースで処理中案件をすべて確認待ちにし、進行中がゼロになった
- 各ケースで直前の合格版へ復元し、復元前後と再点検結果を確認できた
- 各ケースで権限者の人が最後に再開を承認し、停止から再開までの全操作に時刻・操作者・理由・対象が残った

普通のChatで進めた場合は、文章をコピーするか、できたファイルをダウンロードして`完成`フォルダへ入れます。`Work`でデモフォルダを開いて進めた場合は、次の一言で保存を頼めます。

```text
この未公開のAI緊急運転室、三異常ケースの停止→確認待ち→直前の合格版への復元→権限者の再開承認、手作業パック、四項目の時系列ログを、完成フォルダの「安心運用センター」へ「10_AI緊急運転室_最終版」として保存して。三ケースを実際に通せた一言、未確認事項、教材環境のみ・未公開・本物の外部送信なしも表紙に残して。
```

保存した物をもう一度開けたら、今回の課題は完成です。

### 自分の仕事なら

自分の運用へ移す時は「古い資料を使った」一ケースだけへ置き換え、権限者と直前の合格版を決めて四段階を小さく再現します。

### 困ったら藤本に聞く

止まった画面のスクショと、「Lv.180で、ここまでできた：＿＿。ここで止まった：＿＿」を藤本へ見せます。うまく説明できなくても大丈夫です。実在する個人情報や秘密は隠します。
