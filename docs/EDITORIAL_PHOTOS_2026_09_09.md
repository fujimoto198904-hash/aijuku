# 公式投稿に写真を添える

更新：2026年9月9日。ソースへ実装済み。本番は版30のままで、写真対応の公開は未実施です。

## 9月14日の仕上げ（ローカル確認済み・未公開）

- 制作する物を優先して写真を選ぶよう修正。小説・絵本は執筆、音声はヘッドセットや在宅作業、スライドは資料の写真へ。薬局は医療の話題、家族写真は家族の話題に限定します。
- 同じ枠の投稿で写真が偏るハッシュ計算を修正。同じ投稿の写真は引き続き固定です。素材は既存の12種類・24ファイルのまま増やしていません。
- フィード・詳細は480px／960pxから表示幅と画面密度に合う画像をブラウザーが選択。プロフィールは480pxのみ。どちらも遅延読み込みです。
- プロフィールにも小さな写真注記を追加。スマホの写真タイルでは種別やコメント件数を省き、写真と2行の見出しを主役にしました。
- `npm run verify`（ビルド含む）、型検査、変更TS/TSXの限定lint、`git diff --check` が成功。HTTPで24画像・20投稿詳細・10プロフィールを確認。ローカルのブラウザーでPC表示、390px幅のフィード→プロフィール→詳細を確認し、写真の読込と横はみ出しなし・コンソールエラーなしを確認しました。実機検証・本番反映は未実施です。

## 見せ方

- 文字だけになりやすい公式・公式AIの投稿に、仕事・カフェ・家族・農園などの写真を添えます。
- 本文と関連課題から分野を選び、その中で投稿IDに応じて写真を振り分けます。同じ投稿では、フィード・詳細・プロフィールで同じ写真を使います。
- フィードと詳細は横長3:2、プロフィールは軽いサムネイル。カフェ写真は小さい枠でも話し手が見える位置に寄せます。
- 既存の教材紹介6件は、表・メールなどの作例を優先し、そのまま残します。
- 一般会員の投稿には自動で写真を付けません。公式でも、自分で添付した画像がある場合はそちらを優先します。
- 写真のない既存の公式AI投稿にも適用されます。過去の本文を書き換えたり、再投稿したりする必要はありません。

## 素材と容量

`sozai/` の提供済み写真から12種類だけ選びました。個人のプロフィール写真は対象外です。元画像は変更せず、メタデータを取り除いた480px・960pxのWebPを `public/brand/editorial/` に保存します。24ファイル合計564,730バイト。投稿のたびにR2へ複製しません。

画面外の写真は遅延読み込み、表示枠の高さは先に確保します。Sitesの画像配信経路に合わせ、既存と同じく外部の画像最適化URLを使わない構成です。写真には実際の内容に沿った代替テキストと、小さな「イメージ写真」の表示を付けます。写真はAIの生成結果や利用実績の証拠ではありません。

再生成は `cwebp` を用意したMacで `npm run build:editorial-photos`。通常の検証では再生成せず、コミット対象の軽量画像を検査します。

## 検証と公開の境界

`npm run check:editorial-photos` は公式限定、添付画像の優先、分野の選択、同一投稿の固定、異なる投稿での振り分け、24画像の形式・容量・メタデータ除去を確認します。実コンポーネントのHTMLで遅延読み込み・代替テキスト・サムネイルを検査します。`npm run check:ui` / `npm run verify` に含めています。

このスクリプト検査と、上記のローカルブラウザー検証は別の証拠です。スマホ実機・本番での画像取得は別途確認が必要です。本番反映時は、正式URLのフィード・投稿詳細・プロフィールと、画像のHTTP応答を改めて確認してください。

ローカルで `npm run verify`（ビルドを含む）、`npx tsc --noEmit`、変更したTS/TSXの限定lint、`git diff --check` が成功しました。全体のlintがクリーンになったという意味ではありません。`npx tsx scripts/check_editorial_photos_http.ts http://localhost:3187` で、フィード・既存20投稿・10プロフィール・24画像の200応答と画像のバイト一致を確認しました。

既存の投稿テストには、SQLiteの実時計で作るサンプルとNode側の固定時刻が混ざり、実行時刻によって先頭ページの期待件数が変わる問題がありました。隔離テスト内だけで初期サンプルを固定時刻より1日前へ揃えています。本番データやアプリの並び順は変更していません。

朝夕の投稿時刻・上限・本人表示は変更しません。定期タスクは既存の `aistock-1-2` を使い、写真用の重複タスクは作りません。[投稿運用](OFFICIAL_POSTING_ROUTINE.md)を参照してください。

既存タスクの指示を写真中心の方針へ更新し、ACTIVEのまま毎日09:00・19:00で保存しました。写真が表示されるのは、この対応版を本番公開してからです。
